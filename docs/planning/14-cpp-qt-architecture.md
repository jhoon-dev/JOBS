# C++ + Qt 기본 아키텍처와 계약
ADR-008 · 2026-10-25 · 상태 DECIDED_DIRECTION
사용자 결정 위임에 따라 dot이 선택한 기본 방향이다. 실측으로 입증한 최적 성능이나 제품 동등성 판정이 아니다.

## 결정
Windows/macOS 설치형 제품의 기본 언어는 C++, UI 기반은 Qt다. UI와 독립된 C++ 일정 계산 코어, 로컬 저장·자동 복구를 기본으로 설계한다. 처음부터 C#/Rust를 혼합하지 않는다.
Qt Widgets 중심 UI는 세부 설계 우선안이며 Widgets/Quick 조합·Qt 버전·모듈·라이선스·저장 엔진·파일 형식은 검토 후 확정한다.
C#/Avalonia와 Rust는 동시 구현 경로가 아니라 재검토 시 대안이다. 기존 전체 기능 후보와 Parity/Superiority 두 트랙은 유지한다.

## 모듈과 의존 규칙
| 모듈 | 책임·입출력 | 허용 의존 |
|---|---|---|
| Domain | stable ID, 단위·시각·달력·작업·관계·실적·기준선·진단 타입과 불변조건 | 표준 C++와 명시 승인된 기초 라이브러리. Qt UI·파일·DB·네트워크 의존 금지 |
| Calculation | 불변 Domain snapshot + profile/options→CalculationResult/diagnostics/trace | Domain과 버전 고정된 계산 의존. QWidget/QObject·이벤트 루프·화면 문자열 의존 금지 |
| Application | 명령·undo/redo·revision·계산 요청·결과 적용·저장 흐름 | Domain, 추상 계산/저장 포트. UI 컨트롤 직접 참조 금지 |
| Qt UI | WBS·표·간트·편집·오류·접근성·OS 입력 | Application의 명령/조회 계약. DB·파일 직변경과 일정 공식 구현 금지 |
| Persistence/Recovery | 파일 인코딩·schema·원자적 저장·복구·이관 | Domain/저장 포트. 계산 결과를 입력 사실로 바꾸지 않음 |
| Exchange adapters | 외부 형식·profile·ID namespace·손실 보고 | Domain/명시 교환 포트. UI 없이 import/export 가능한 경계 |
| Optional services | 협업·동기화·권한·공유 자원·서버 연결 | 명시 서비스 포트. 로컬 핵심 흐름에 상시 서버 의존을 강제하지 않음 |

의존 방향은 UI/어댑터→Application→Domain이며 Calculation은 Domain을 사용한다. Domain/Calculation이 UI·저장 구현을 역참조하면 경계 위반이다. 기획 검증은 인터페이스·의존표 검토, 향후 구현 검증은 UI 없는 계산 fixture 실행과 의존성 검사다.

## 계산 실행 계약
입력은 document ID·revision/hash·engine/profile/calendar/tzdb 버전·scope·options·취소 토큰이다. 출력은 input revision과 함께 영역별 상태·일정/자원/진척/원가 결과·진단·원인 trace를 반환한다.
Application은 완료 시 현재 revision과 대조한다. 다른 revision 결과는 stale로 보존하고 최신 편집을 덮어쓰지 않는다. 계산 중 actual/baseline/현재 입력을 부분 수정하지 않는다.
UI는 계산 식을 재구현하지 않고 결과를 표시한다. 로캘·픽셀·OS 현재 시각을 계산 입력으로 암묵 사용하지 않는다.
긴 계산·교환은 UI 스레드 밖에서 수행한다. 취소·실패는 VALID 결과로 승격하지 않는다. 메모리/시간 한도와 프로세스 격리는 이후 검증하며 처음부터 IPC를 강제하지 않는다.

## 파일과 복구 계약
파일은 document ID·schema version·content revision·필수 단위/달력/profile 참조·무결성 정보·원본 외부 매핑을 포함하는 논리 계약을 갖는다. 확장자·컨테이너·DB는 미정이다.
명시 저장은 이전 정상본을 보존하며 임시 저장→무결성 검사→commit/교체→성공 통지 순서로 설계한다. 플랫폼별 flush/rename/파일시스템 가정은 별도 검증한다. 실패 시 성공 표시를 하지 않으며 손상본으로 정상본을 교체하지 않는다.
자동 복구 checkpoint, 명시 저장, backup, undo, 승인 baseline은 별도 객체다. 복구 기록은 revision·checksum·완료 marker·기준 정상본을 연결한다. 미완료 checkpoint를 최신 정상본으로 선택하지 않는다.
재시작 시 원본과 복구본의 revision·시각·차이를 미리 보여주고 선택 복구를 새 버전으로 수행한다. 복구 불가능 구간은 숨기지 않는다.
파일 잠금과 외부 변경 감지를 병행한다. 중복 열기·동기화 폴더·네트워크 파일시스템의 잠금 신뢰성을 가정하지 않는다. 충돌이면 읽기전용·복사본·재열기 선택을 제공하고 무음 덮어쓰기를 금지한다.
이관은 원본 백업→schema 검사→별도 대상 변환→검증→열기 순서다. 신버전 미지원은 안전 거절, 실패는 원본 유지. 앱 rollback과 schema rollback은 분리한다.
권한 거부·디스크 부족·강제종료·장치 제거·잠금 충돌·이관 중단·손상 입력을 수용시험으로 둔다. 절대 무손실을 보장하지 않는다.

## 선정 유지·재검토 기준
| 게이트 | 필요한 증거 | 미충족 시 조치 |
|---|---|---|
| 대형 WBS/간트 | 같은1만/10만 작업 fixture의 정확한 편집·undo·동기화·반응시간/메모리 | 원인 분리·설계 보완 후 재평가. 요구 불충족이 지속되면 Qt 세부 UI안 또는 Avalonia 대안 재검토 |
| 계산 정확성 | F01~12와 달력/DST/profile 추가 사례, OS별 결과·진단 재현 | 알고리즘/자료형/계약 문제부터 수정. 언어 변경을 정확성 해결로 간주하지 않음 |
| 접근성/IME | Windows/macOS 키보드·스크린리더·고DPI·IME 전체 업무 | 커스텀 간트 의미 모델 보완, 필수 업무 해결 불가 시 UI기반 재검토 |
| 저장/복구 | 저장 성공본 보존·장애 주입·이관·충돌 시험 | 저장 형식/엔진/프로토콜 재검토. 무음 손실이 있으면 출시 게이트 통과 불가 |
| OS별 배포 | 지원 매트릭스·오프라인 설치·업데이트 중단·제거의 문서 보존 | 패키징/런타임 정책 재검토, 실제 배포는 별도 승인 범위 |
| 라이선스/운영 | 선택 Qt 버전·각 모듈·SDK·배포 도구의 의무/BOM/유지 비용 | 수용 불가 조건이면 모듈 교체·범위/제품 정책 검토 후 ADR 재개 |

정확성·내구성·접근성 필수 실패를 평균 성능 점수로 상쇄하지 않는다. 재검토는 증거·영향·대안·결정 사유를 새 ADR로 남긴다. 기술 방향 선택은 유료 구매·약관 동의·서명 인증서 발급·권한 변경·실제 배포·구현 착수 승인이 아니다.
