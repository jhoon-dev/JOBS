# 제품기획과 PRD
상태: 상세 설계 PROPOSED. 사용자 목표·PRD 중심 진행·독립 프로젝트 경계·Windows/macOS 설치형 방향은 CONFIRMED.
사용자는 PRD 중심의 진행을 확정했다. 이 문서는 JOBS 기획의 중심이며, 상세 설계와 단계별 작업은 아래 요구사항 ID를 참조한다.

## 제품 문제
복잡한 프로젝트의 구조, 일정, 인력, 원가와 변경 영향을 일관된 근거로 관리해야 한다. 초기 입력은 간단해야 하지만 계산 결과는 캘린더·의존관계·실적·제약과 연결되어 설명 가능해야 한다.
경쟁 제품 전체 기능은 장기 후보이며 각 제품군·버전별 차이는 원문 확인 후 추적한다. 마케팅상 유사성으로 동등성을 선언하지 않는다.

## 제안 사용자
프로젝트 매니저는 WBS·일정·기준선·변경을 관리한다. 스케줄러는 네트워크와 계산 진단을 검토한다. 자원 관리자는 공유 인력·능력·기간별 가용량을 관리한다. 담당자는 실적과 잔여 작업을 보고한다. 원가 관리자는 예산·실적·예측을 비교한다. PMO는 포트폴리오와 표준을 관리한다. 관리자·감사자는 권한·변경 이력·복구를 확인한다.
첫 검증 산업과 프로젝트 규모는 사용자 결정이 필요하다.

## 핵심 경험과 요구사항
PRD-01: 프로젝트명·시작일·기본 근무달력으로 초안을 만들고 작업명 목록을 붙여넣는다. 선택하지 않은 의존관계·자원은 미설정으로 표시한다.
PRD-02: 작업을 WBS로 구조화하고 표·간트·네트워크에서 같은 ID와 데이터를 편집한다.
PRD-03: 계산 시 입력 버전·정책·진단·결과를 고정한다. 변경 전후 완료일과 원인을 비교한다.
PRD-04: 승인된 계획을 기준선으로 저장한다. 기준선 변경은 새 버전과 승인 사유로 남긴다.
PRD-05: 상태일 기준 실적·잔여량·예측을 입력하고 계획 대비 편차를 설명한다.
PRD-06: 자원 과부하를 먼저 보여주고 조정안을 별도 시나리오로 비교한다.
PRD-07: 원가·성과·위험·포트폴리오·협업·교환·관리 기능을 추적 가능한 후보로 유지한다.

## 품질 요구
동일 입력과 계산 정책이면 동일 결과가 나와야 한다. 오류 발생 시 부분 결과를 정상 일정처럼 보여주지 않는다. 모든 날짜와 수치는 단위·달력·상태일·출처를 확인할 수 있어야 한다.
접근성: 키보드로 표와 작업 상세를 다룰 수 있고 색 외의 편차 표시를 제공한다. 국제화: 표시 언어·날짜 형식·시간대·통화와 내부 저장 표현을 분리한다.
성능은 임의 보장하지 않는다. 제안 검증 구간은 1천/1만/10만 작업이며 의존관계 수·자원 수·하드웨어·동시 사용자와 함께 측정한다.

## 검증 가능한 초기 완료조건
작업 추가→WBS→FS 의존→휴일 반영 계산→기준선 저장→실적 입력→예측 비교를 하나의 시나리오로 재현한다. 수동 계산 가능한 사례의 기대 결과와 맞아야 한다. 잘못된 순환·달력·단위는 명시적으로 거절한다. 가져오기 손실은 항목별로 드러내고 사용자 확인 없이 누락하지 않는다.
이는 첫 검증 범위이며 전체 제품 동등성 완료조건이 아니다.

## PRD로 진행 관리하기
각 작업에는 PRD ID, 기능 ID, 결정 의존성, 예상 산출물과 검증 증거를 붙인다. 상태는 후보/설계/구현/검증을 구분한다. 아래의 초기 기획 기록과 후속 구현 착수·검증 기록을 날짜별로 구분한다. 요구사항 또는 완료조건이 없는 변경은 이 PRD를 먼저 갱신한 후 구현한다.
변경 요청은 사용자 문제→요구사항 영향→계산·데이터·화면·교환 영향→수용조건 변경 순서로 검토한다. 보조 문서만 바꿔 PRD와 다른 동작을 확정하지 않는다.
다음 검토는 공식 카탈로그 전행 매핑, 계산 전문 검토 반영, 첫 사용 환경 확인 순서다. 자료 접근 차단은 전체 기획의 완료로 처리하지 않는다.
갱신: 공식 Library read로 전체 본문을 확인하여 337행 초안 매핑과 39과제 보존, 계산 전문 원고 통합을 진행했다. 원본 bytes materialization과 행별 상세 설계 승인·실행 검증은 별도 미완료다. PRD-08을 포함한 8개 PRD 항목은 상위 요구사항 묶음이며 세부 요구는 10-detailed-requirements.md에서 이어 검토한다.

## 확정된 최종 목표와 플랫폼
사용자 확정: 기존 상용 PM 소프트웨어를 능가하는 전문 도구를 목표로 한다. Windows/macOS 설치형 데스크톱 제품으로 진행한다. 전체 기능 후보를 유지하며 PM Canvas 개인 웹 프로토타입과 분리한다.
사용자 결정 위임에 따라 C++ + Qt를 기본 방향으로 선택했다. UI 독립 계산 코어와 로컬 저장·자동 복구를 기본으로 한다. 세부 Qt 모듈/버전·DB·라이선스·사업모델은 미확정이다. 아래 평가·구조·완료조건은 설계 제안이며 우월성 수치나 출시 약속이 아니다.

## Parity와 Superiority 검증 트랙
Parity는 제품군·버전·빌드와 semantic profile별 기능·계산·제약·교환 결과를 비교한다. import, 원본 보존, JOBS 재계산, 왕복 호환성은 별도 판정이다.
Superiority는 경험·성능·설명력의 개선을 별도 검증한다. 한 트랙 통과가 다른 트랙 통과를 의미하지 않는다.

| 제안 ID | 목표·측정 지표 | 평가 방법 |
|---|---|---|
| SUP-01 | 첫 유효 계획까지 시간·오류율·과업 성공률 | 같은 과업을 신규/숙련 사용자별 비교, 도움 요청과 숙련도 기록 |
| SUP-02 | 편집·계산·가져오기 중앙값/P95, 메모리·실패율 | 같은 하드웨어·데이터·그래프·설정에서 반복 측정, 의미 생략으로 얻은 속도 제외 |
| SUP-03 | 지연 원인 판별 정확도·소요시간·오설명 비율 | 전문가 정답 사례를 블라인드 평가, 결과에서 원인 입력·경로로 연결 확인 |
| SUP-04 | 필드별 보존·손실·재계산 차이·무음 손실 | 제품 빌드별 fixture와 왕복 비교, 손실 사유와 영향 공개 |
| SUP-05 | 복구 성공·시간, 키보드 과업 성공·접근성 결함 | 장애·충돌·복구 및 보조기술 고정 과업 수행 |

목표값은 비교 기준과 측정 환경을 정한 뒤 결정한다. 데이터셋·빌드·정책·표본·반복·불확실성을 보존하며 근거 없는 개선율·처리량·일정은 약속하지 않는다.

## 최신 기술 방향 결정
C++ + Qt 선택은 사용자 결정 위임에 따라 dot이 정한 기본 방향이다. 이전의 '기술 후보만 있음' 상태를 대체한다. UI-코어 의존 규칙·계산 revision·파일/복구 계약·게이트 실패 시 재검토는 14-cpp-qt-architecture.md를 따른다. 검증된 최적 성능이나 구현 승인이 아니며 C#/Rust 초기 혼합은 하지 않는다.

## PRD-08 프로젝트별 독립 파일 — 최우선 확정 요구
Office처럼 프로젝트별 JOBS 자체 파일을 새로 만들기/열기/저장/다른 이름으로 저장하고, 이동 후 Windows/macOS에서 이어 연다. 계정·서버 없이 기본 작업을 수행한다. MS Project/Primavera 교환은 별도 호환성 단계다. 확장자·내부 컨테이너/DB는 미정이다.
세부 계약과 수용조건은 15-project-file-contract.md의 FILE-01~10/FILE-T01~09다. 단일 전달 파일과 자동복구·잠금·첨부·외부참조를 구분한다. 클라우드/공유폴더는 동시편집을 자동 보장하지 않는다. SQLite 사용 시 main-only 복사로 WAL 변경을 누락하지 않도록 snapshot/backup 계약을 검증한다. 단계 A/B의 최우선 수직 흐름이며 기존 전체 기능 후보는 유지한다.

Windows/macOS의 도메인·UI·저장/복구·대용량 회귀와 네이티브 화면을 검증한다. 1,024×650의 작은 창에서도 작업 표에 최소 4행을 표시하고, 높이 760 미만에서는 긴 도움말을 접고 진단 영역을 줄인다. F1/편집 메뉴에서 도움말을 계속 열 수 있다. |

정확한 붙여넣기/선택/삭제 보호와 제한은 [작업 편집 계약](../task-editing.md)을 따른다. 기본 표의 모델 전환, 자동 행 확장 붙여넣기, 끌어다 놓기 행 재배치와 다중 작업 속성 대화상자는 후속 증분이다. 현재 표 구조를 유지하면서 작업 ID를 기준으로 편집하며 제품 전체 접근성/교환 동등성을 이번 완료로 표시하지 않는다.

## 2026-10-27 Project XML 교환 첫 증분

사용자 승인에 따라 J-15 교환의 첫 범위를 구현한다. 개발 전에 이 완료조건과 [XML 교환 계약](../project-xml.md)을 커밋한다. XER/MPP와 외부 제품 계산 동등성은 후속 게이트다.

| ID | 요구사항 | 이번 완료조건 |
|---|---|---|
| XML-01 | 제한된 MSPDI 계획 가져오기 | Microsoft Project XML namespace의 단일 프로젝트에서 UID 기반 작업/WBS, 정수 근무분 기간·마일스톤, FS/SS/FF/SF 및 정수 근무분 지연, 날짜 제약/마감일, 표현 가능한 주간 달력·전일 휴일, work 자원/정률 배정을 매핑한다. 중복 UID/고아 참조/순환·정밀도 손실·지원 불가 달력/외부 관계는 차단한다. 원본 Start/Finish를 확정 실적이나 고정 일정으로 오인하지 않는다. |
| XML-02 | 원본 보존·변환 진단 | 가져오기 미리보기에서 미지원 정보·가정과 건수를 표시한다. 승인 시 새 교환 폴더에 project.jobs, original.xml 원본 바이트, SHA-256·제품 버전·UID 매핑·진단을 가진 conversion.json을 함께 게시한다. 기존 폴더 덮어쓰기·실패 시 문서 교체·부분 패키지 게시를 금지한다. 원본은 .jobs 내부가 아닌 동반 파일이며 .jobs만 사본 저장할 때 자동 동반 복제하지 않음을 표시한다. |
| XML-03 | 계획 XML 내보내기 | 전체 프로젝트 계획의 작업/WBS·관계·달력·자원/배정을 project.xml로 내보낸다. 미정 기간은 미정으로 유지하며 기준선·실적·원가·시나리오·공수/분할 등 미지원 항목을 conversion.json에 명시한다. 원본 JOBS 스냅샷 source.jobs를 동봉하고 원본 문서의 dirty/revision/undo를 변경하지 않는다. 새 폴더 단위로 원자적으로 게시한다. |
| XML-04 | 독립 호환 판정·회귀 | 가져오기 성공·원본 보존·JOBS 재계산·외부 왕복 호환을 각각 기록한다. 파싱 성공을 외부 계산 동등성으로 선언하지 않는다. 골든 입력의 독립 기대값, 네 관계/음수 지연, 달력/배정, 오류/취소/기존 파일 보호, 저장 재열기, JOBS 지원 부분 재수입과 독립 XML reader 검사를 Windows/macOS에서 수행한다. 실제 Microsoft Project에서 열고 재저장하는 검증은 별도 미검증 상태다. |

## 2026-10-27 Primavera XER 교환 증분

사용자 요청으로 J-15의 다음 형식인 XER을 추가한다. 아래 요구사항과 [XER 교환 계약](../primavera-xer.md)을 먼저 커밋한 뒤 개발한다. 지원 부분의 계획 변환과 실제 P6 계산/재저장 호환은 별개다.

| ID | 요구사항 | 이번 완료조건 |
|---|---|---|
| XER-01 | 단일 프로젝트 계획 수입 | ERMHDR/%T/%F/%R/%E를 읽어 PROJECT·PROJWBS·TASK·TASKPRED·CALENDAR·RSRC·RSRCRATE·TASKRSRC의 ID/WBS/기간·네 관계/지연·지원 제약·주간 달력/전일 휴일·자원/정률 배정을 매핑한다. 다중 프로젝트/교차 프로젝트 관계·중복/고아/순환 참조·LOE/WBS summary 작업·미지원 달력/보조 제약을 차단한다. 기간 기반 계획으로 변환하고 실적/원가를 만들지 않는다. |
| XER-02 | 문자·수치·손실 계약 | UTF-8/BOM과 명시 선택 Windows-1252를 지원하며 CP949 등 다른 인코딩을 추측하지 않는다. 시간은 6자리 소수 시간에서 정수 근무분으로 변환하되 표현 오차 한도와 진단을 적용한다. 미정/0을 구분하고, 미지원 필드/테이블·계산 정책 차이·원본 Activity ID·헤더/인코딩/ID 매핑을 진단 및 원본에 보존한다. |
| XER-03 | 계획 수출·원자적 보존 | 파일 메뉴에 가져오기/내보내기와 변환 미리보기를 추가한다. 새 교환 폴더 단위로 original.xer+project.jobs 또는 project.xer+source.jobs와 conversion.json을 함께 게시한다. 기존 폴더/원본 파일 덮어쓰기·취소/오류/오래된 미리보기의 부분 문서 교체를 금지한다. 읽기 전용/미저장 문서의 전체 입력 사본을 내보낼 수 있고 revision/undo/승인 기록을 변경하지 않는다. |
| XER-04 | 독립 검사·플랫폼 회귀 | 수작업 골든 입력/수치 기대값·지원 부분 재수입·원본 바이트/해시·승인/실적/원가 사본 보존·불가 입력/한도·UI 취소/미저장 경고/오래된 입력/읽기 전용을 검사한다. 독립 TSV reader와 MPXJ 고정 버전으로 실제 수출 XER의 구조/작업·관계·달력·배정을 재열기 검사하고 Windows/MSVC/macOS CI·네이티브 화면·기존 성능 회귀를 통과한다. 실제 Oracle P6 호환은 별도 미검증으로 남긴다. |
