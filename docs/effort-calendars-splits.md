# 공수 기반 일정·작업 유형·자원 달력·분할 작업

2026-10-26 사용자 후속 구현 요청. Microsoft Project/Primavera 파일 호환·제품 동등성의 승인을 뜻하지 않는다.

## 화면 사용

1. 자원을 등록하고 작업에 배정한다. 100%는 자원 1단위다. 인력과 장비의 생산성 배수는 1이며, 합계 공수는 배정 단위시간의 합이다. 인시/장비시간을 별도 생산량으로 환산하지 않는다.
2. 프로젝트 → **선택 작업 공수·유형·분할**에서 작업 유형, 이번 변경의 입력 기준, 기간(근무분) 또는 공수(자원시간)를 입력한다. 표의 기간 셀도 편집할 수 있다. 공수 기준 작업의 유효 계획에서는 계산된 활성 기간을 보여 준다.
3. 공수/유형/분할 적용은 한 번의 실행 취소 대상이며, 적용 후 일정을 자동 계산한다. 기존 기준선·실적·원가 이력은 변경하지 않는다.
4. 프로젝트 → 작업 달력 등록·편집에서 달력을 정의하고 **자원 등록·가용량 → 자원 달력**에서 선택한다. 작업과 자원은 같은 달력 라이브러리를 사용한다. F9로 재계산한다.
5. 자원 → 기간별 부하·평준화 비교에서 수동 분할을 포함하는 원본/직렬 평준화 시나리오를 비교한다. 보고서에는 공수/작업 유형, 분할 중단, 자원별 달력, 실행 배정 구간이 추가되며 XLSX/PDF에도 포함된다.

## 유지값과 편집 규칙

| 작업 유형 | 기간 편집 | 공수 편집 | 기존 배정률 변경/배정 추가·삭제 |
|---|---|---|---|
| 고정 기간 | 배정률 유지, 공수 재계산 | 기간 유지, 배정률 비례 조정 | 기간 유지, 공수 재계산 |
| 고정 공수 | 공수 유지, 배정률 비례 조정 | 배정률 유지, 완료일 재계산 | 공수 유지, 완료일 재계산 |
| 고정 단위 | 배정률 유지, 공수 재계산, 기간 기준으로 전환 | 배정률 유지, 완료일 재계산, 공수 기준으로 전환 | 기존 공수 유지, 완료일 재계산 |

고정 단위는 현재 계산 기준도 저장한다. 첫 배정이거나 기존 계획 공수가 0이면 배정 후에도 기간 기준을 유지한다. 같은 배정을 다시 적용하는 것은 변경이 아니다. 배정 추가는 작업 유형에 따른 위 정책이며 자동 생산성/인원별 역할 재구성을 가정하지 않는다.

배정률은 정수%이므로 역산 시 자원별 비율을 유지해 반올림하고 양수 배정은 최소 1%로 둔다. 가용량을 넘는 배정도 입력할 수 있으며 부하 화면에서 진단한다. 반올림과 달력 때문에 요청 공수/기간과 산출값이 다를 수 있다. 고정 공수의 목표 공수는 항상 보존한다. 배정률 역산에는 입력 기간을 적용한 유효한 전체 계획과 겹치는 양수 자원 가용시간이 필요하다. 실패하면 입력 전체를 보존한다. 배정률 편집, 유형 변경, 자원 달력 변경으로 실제 날짜·실제원가를 수정하지 않는다.

## 계산 계약

새 정책은 `native-effort-split-v1`, 엔진은 `jobs-effort-1.0`이다. 기존 `native-fs0-workminutes-v1` / `native-pdm-taskcal-v1` / `native-pdm-constraints-v1`의 계산 결과는 기존 엔진으로 재현한다. 첫 공수/유형/분할 설정이나 명시 자원 달력 배정이 새 정책을 선택한다.

- 단위: 기간은 정수 작업 근무분. 공수 `workUnitMinutes`는 1/100 자원분, 6,000=1 자원시간, 범위 0~500,000,000,000. 배정률 100 × 1분=100 공수 단위분이다. 시간 입력은 가장 가까운 단위분으로 반올림한다. 소수 단위분·초 단위 스케줄은 지원하지 않는다.
- 기간 기준은 작업 달력에서 중단을 뺀 활성 근무분을 유지한다. 자원 달력이 작업 중 일부만 겹치면 그 시간만 공수를 계산한다. 자원 달력은 고정 기간의 완료일을 늦추지 않는다.
- 공수 기준은 작업 달력에서 중단을 제외하고, 각 자원 달력과 교집합을 구한 뒤 시간별 배정률을 적분해 목표 공수에 도달한다. 자원 부재/달력 교집합 없음과 0 공수는 구분한다. 양수 공수에 미배정이면 불완전, 교집합/20년 가용시간 부족이면 충돌이다. 공수 0은 마일스톤이다.
- 완료 경계는 정수분으로 올림한다. 마지막 분은 그 분에 근무하는 자원의 원래 배정률 비중대로 공수를 배분한다. 정수 나눗셈의 잔여는 자원 ID 오름차순으로 1씩 배분한다. 그 분의 공수·부하·원가가 입력 목표를 초과하지 않는다. 원래 입력 배정률은 유지한다.
- 자원 달력 빈값은 프로젝트 기본 달력+프로젝트 휴일이다. 명시 달력은 독립된 요일·시간대·휴일이며 작업 달력에 우선하지 않는다. 자원 가용량 예외는 근무 구간 안의 최대 배정률이다. 가용량은 일정의 생산성 배수가 아니며 별도 평준화가 용량 제약을 적용한다.
- FS/SS/FF/SF와 signed lag, 8종 날짜 제약·마감 경고를 함께 적용한다. 완료 대상 관계/제약은 가변 공수 완료 함수의 역산으로 배치하며 명목 기간을 빼지 않는다. 지연/선행은 중단을 제외한 후행 작업 달력 근무분이다. ALAP은 현재 ASAP 완료일 안에서 후행을 늦추지 않는 배치이며 계획에서만 적용한다. 총/자유 여유는 해당 작업 활성 달력 근무분이다.
- 자원 평준화 `serial-effort-split-v1`는 기존 3종 우선순위와 입력 순서 동률 해소를 사용한다. 공수와 수동 분할을 유지하고 시작을 지연시켜 배치한다. 자동으로 용량에 맞춰 작업을 추가 분할하는 최적화는 후속 범위다. 미정 가용량·탐색 한도·하드 날짜 충돌은 전체 결과를 불완전/충돌로 반환하며 부분 일정을 확정하지 않는다. 예측/평준화의 여유/임계·ALAP 재배치는 미산정이다.

## 분할과 추적

중단 구간은 `YYYY-MM-DD HH:mm | YYYY-MM-DD HH:mm`을 날짜순으로 한 줄씩 입력한다. `[중단 시작, 재개)`의 절대 civil 시각이며 최대 1,000개, 시작<재개, 비중복이다. 경계가 맞닿는 구간은 허용한다. 프로젝트 시작 전/완료 뒤의 구간은 겹치는 부분만 영향을 준다. 날짜 이동 후에도 중단 날짜는 유지한다. 모두 지우면 분할을 해제한다. 간트는 활성 구간과 중단/비근무 점선을 구분하며 공수 기준 작업은 자원 달력에 가용한 배정 구간을 합쳐 표시한다.

중단 중 해당 작업의 배정/공수/자원비는 0이며 다른 작업은 그 자원을 사용할 수 있다. 고정비의 균등 발생은 중단을 제외한 작업 달력 활성 시간에 배분한다. 자원비는 실제 계획 배정 구간·유효일 단가에 따르며 자원별/일별 누적 공수에 대해 한 번 반올림한다. 승인 기준선 BAC/PV/EV는 당시 입력·달력·공수·중단의 불변 사본으로 계산한다. AC는 기존 누적 보고값이다.

상태일의 공수 기준 작업은 실적 창에 **명시 잔여 공수(h)**를 입력한다. 과거 기간 보고를 공수로 추정하지 않는다. 잔여 공수 보고가 없으면 예측을 불완전으로 표시한다. 완료 보고는 잔여 공수 0으로 취급하고 미래 수요가 없다. 실제 시작/완료는 고정하고 잔여 공수만 상태일·선행·달력·중단 이후에 배치한다. 공수 기준의 미완료 보고는 잔여 기간을 요구하지 않고 기간 진척률을 미정으로 둔다. 기간 기준으로 유형을 변경한 뒤 기간 추정이 없으면 새 잔여 기간 보고가 필요하다. 기간 기준 작업은 기존 잔여 기간 정책을 계속 사용한다. 실제 인시/자원별 실적 공수 원장과 기간별 가변 배정률은 후속 범위다.

간트 이동은 공수/작업 유형을 유지하고 날짜 제약을 변경한다. 오른쪽 끝 편집은 위 기간 편집 정책을 따른다. 실제 시작 이력/예측/읽기 전용/오래된 결과의 드래그 제한은 유지한다. 분할 중단의 절대 시각은 드래그로 이동하지 않는다.

## 파일·복구와 검증

native `.jobs` schema 9에 taskType/workDriven/workUnitMinutes/breaks, 자원 calendarId와 명시 잔여 공수를 저장한다. 새 필드는 새 profile의 계획/기준선/시나리오에만 인코딩해 기존 승인 입력을 재해석하지 않는다. 실적의 잔여 공수는 존재할 때만 저장한다. native schema 1~8은 원본 보존 SaveAs로 이관한다. 복구 envelope schema 1은 내부 projectSchema 6/7/8/9를 지원한다. 입력·복구·기준선 재검증, 원자 저장·해시·잠금·충돌 방지, 실행 취소 정책은 기존 계약을 따른다.

`effort_work_calendar_split`은 유형 편집 행렬, 혼합 달력·휴일·교집합 없음, 중단의 공수/원가/부하, 마지막 1분 정확 보존, 4종 관계·제약·ALAP, 평준화·실제 보존·명시 잔여·기준선 PV·schema9·복구/실행 취소를 검증한다. `effort_ui`는 모달 입력·잘못된 구간의 무변경·자동 재계산·간트 중단·자원 달력 선택·읽기 전용을 검증한다. 보고서 fixture는 독립 openpyxl/pypdf로 수치·공백 구간·한국어/출처를 검사한다. 외부 상용 도구 비교, 자동 분할 최적화, 초 단위·타임존/DST·생산량·실제 자원 공수와 대규모 성능은 별도 검증 범위다.

macOS CoreText의 비공개 시스템 UI 글꼴은 Qt PDF의 시각 콜론을 제어문자로 매핑하는 문제가 확인되어, PDF에 설치된 공개 Arial/Helvetica/Noto Sans를 사용하고 한국어는 Qt의 시스템 대체 글꼴을 사용한다. 독립 reader는 제어문자 혼입을 거절하고 날짜·시각의 실제 텍스트를 검사한다. Unicode 합자 표현만 NFKC로 정규화하며 잘못된 제어문자를 콜론으로 치환하지 않는다.
