# 파일명 보존과 편집 성능

2026-10-27 사용자 승인 범위. PRD FILE-CASE-01, EDIT-PERF-01~03을 구체화한다. 구현 전에 `baaa01c`로 계약을 커밋했고, 파일명 수정과 회귀는 `f4655db`, 측정 도구는 `3570d28`로 분리했다. 완료/측정 결과는 검증 후 추가한다.

저장할 경로의 이름은 원래 대소문자를 보존한다. 기존 파일 동일성은 파일 시스템 식별로 판정한다. 신규 경로의 생성/잠금은 해당 파일 시스템의 규칙과 기존 create-only 저장을 따른다. 물리 디렉터리 목록의 이름을 검사하며 정규화 함수끼리 비교하는 테스트로 대체하지 않는다.

실행 취소는 수정된 입력의 전후 변경분을 보존한다. 동일 길이 벡터는 변경 요소, 삽입/삭제는 공통 앞뒤를 제외한 구간을 저장하여 순서와 ID를 되돌린다. scalar와 상태일도 누락 없이 보존한다. 파일에는 이력을 직렬화하지 않는다. 최대 100단계 및 추정 32MiB 정책을 유지한다. 긴 이름 등 큰 실제 변경은 한도를 넘을 수 있다. 실패는 문서/redo/dirty/revision/파일을 바꾸지 않으며 변경 없는 입력은 이력을 만들지 않는다. 승인·제출 원장은 삭제 가능한 이력에 넣지 않는다.

일반 이름 변경은 이미 검증된 문서에서 이름만 검증하고 변경한다. 일반 편집/undo도 불변 원장을 복사하지 않도록 가능한 경로를 분리한다. 복잡한 구조/공수 변경의 전체 검증을 임의로 생략하지 않는다. 표는 전체 행을 보존하면서 항목을 재사용하고, 구조가 바뀌지 않은 트리를 재생성하지 않는다. 결과가 오래되면 예전 날짜·강조 표시를 지우고 선택/정렬/필터를 갱신한다.

측정은 기존 결정적 1천/1만 작업 fixture를 사용한다. 기준선 0/3개, 셀 이름/일반 기간, undo/redo와 100회 이름 변경 이력 보존을 검사한다. 문서 처리 시간과 표 셀 변경→갱신→이벤트 처리 시간을 별도 기록한다. 화면 측정은 자동 저장을 끄고 간트·표 화면을 갱신한다. 단일 프로세스 원시 표본과 중앙값/관측 P95, 실제 남은 이력/추정량을 기록하며 OS 페인트 완료 지연/FPS나 실제 사용자 키보드 전체 경로를 보장하지 않는다. 공수 역산·실적/배정 계산·매우 큰 원장·출력은 이번 지표에 포함하지 않는다.

전후 같은 Release 도구/fixture/반복 횟수/플랫폼으로 측정한다. 실행 시 HEAD/dirty와 빌드 시 제품 소스 해시를 함께 남겨 재설정 없는 재빌드에서도 이전 리비전으로 오인하지 않게 한다. 일반 CTest와 별도 측정 스크립트로 재현하며 결과 파일 실패/시간 초과는 정상 표본으로 합치지 않는다. 전체 모델 전환·모든 편집의 비동기화는 후속 증분이며 이번 완료로 주장하지 않는다.
