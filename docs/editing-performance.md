# 파일명 보존과 편집 성능

2026-10-27 사용자 승인 범위. PRD FILE-CASE-01, EDIT-PERF-01~03을 구체화한다. 구현 전에 `baaa01c`로 계약을 커밋했고, 파일명 수정과 회귀는 `f4655db`, 측정 도구는 `3570d28`로 분리했다. 완료/측정 결과는 검증 후 추가한다.

저장할 경로의 이름은 원래 대소문자를 보존한다. 기존 파일 동일성은 파일 시스템 식별로 판정한다. 신규 경로의 생성/잠금은 해당 파일 시스템의 규칙과 기존 create-only 저장을 따른다. 물리 디렉터리 목록의 이름을 검사하며 정규화 함수끼리 비교하는 테스트로 대체하지 않는다.

실행 취소는 수정된 입력의 전후 변경분을 보존한다. 동일 길이 벡터는 변경 요소, 삽입/삭제는 공통 앞뒤를 제외한 구간을 저장하여 순서와 ID를 되돌린다. scalar와 상태일도 누락 없이 보존한다. 파일에는 이력을 직렬화하지 않는다. 최대 100단계 및 추정 32MiB 정책을 유지한다. 긴 이름 등 큰 실제 변경은 한도를 넘을 수 있다. 실패는 문서/redo/dirty/revision/파일을 바꾸지 않으며 변경 없는 입력은 이력을 만들지 않는다. 승인·제출 원장은 삭제 가능한 이력에 넣지 않는다.

일반 이름 변경은 이미 검증된 문서에서 이름만 검증하고 변경한다. 일반 편집/undo도 불변 원장을 복사하지 않도록 가능한 경로를 분리한다. 복잡한 구조/공수 변경의 전체 검증을 임의로 생략하지 않는다. 표는 전체 행을 보존하면서 항목을 재사용하고, 구조가 바뀌지 않은 트리를 재생성하지 않는다. 결과가 오래되면 예전 날짜·강조 표시를 지우고 선택/정렬/필터를 갱신한다.

측정은 기존 결정적 1천/1만 작업 fixture를 사용한다. 기준선 0/3개, 셀 이름/일반 기간, undo/redo와 100회 이름 변경 이력 보존을 검사한다. 문서 처리 시간과 표 셀 변경→갱신→이벤트 처리 시간을 별도 기록한다. 화면 측정은 자동 저장을 끄고 간트·표 화면을 갱신한다. 단일 프로세스 원시 표본과 중앙값/관측 P95, 실제 남은 이력/추정량을 기록하며 OS 페인트 완료 지연/FPS나 실제 사용자 키보드 전체 경로를 보장하지 않는다. 공수 역산·실적/배정 계산·매우 큰 원장·출력은 이번 지표에 포함하지 않는다.

전후 같은 Release 도구/fixture/반복 횟수/플랫폼으로 측정한다. 실행 시 HEAD/dirty와 빌드 시 제품 소스 해시를 함께 남겨 재설정 없는 재빌드에서도 이전 리비전으로 오인하지 않게 한다. 일반 CTest와 별도 측정 스크립트로 재현하며 결과 파일 실패/시간 초과는 정상 표본으로 합치지 않는다. 전체 모델 전환·모든 편집의 비동기화는 후속 증분이며 이번 완료로 주장하지 않는다.

첫 변경분/행 캐시 측정 뒤 자동 열 너비의 반복 탐색이 남아 있음을 확인했다. 열 너비는 현재 보이는 행을 기준으로 산정하며 화면 밖 값은 원본/복사에 그대로 남긴다. 이는 Qt 6.8의 [resizeContentsPrecision 계약](https://doc.qt.io/qt-6.8/qheaderview.html#setResizeContentsPrecision)에 따른다. 모델 값 알림도 행 구간별로 묶되 행 삽입/삭제 알림을 차단하지 않는다.

로컬 측정 후 전체 CPU 98% 부하를 확인해 작은 입력의 시간 비교를 확정 근거로 삼지 않는다. 같은 CI 실행기에서 측정 도구 도입 커밋 `3570d28ed176aae2d90fd34e5efb84f6f096753f`와 현재 버전을 별도 빌드하여 1천/1만·기준선 0/3개·각 7표본을 비교한다. 원시 값과 코드/환경 식별을 함께 보존한다. 이전 버전은 이력 100단계를 보장하지 않는 참조이며 현재 버전만 100단계/32MiB 검증을 요구한다. 성공/실패는 정합성으로 판정하며 벽시계 개선율을 CI 통과 임계값으로 사용하지 않는다.

## 구현과 검증

파일 경로는 대소문자를 보존한다. `ProjectStore::sameFile`을 별도로 두고 실제 파일의 동일성은 `std::filesystem::equivalent`로 판정한다. 새 파일은 기존 파일 시스템 잠금과 create-only 저장을 유지한다. 테스트는 정규화 문자열 대신 실제 디렉터리의 파일 이름을 검사한다. Unicode 정규화만 맞춰 비교하며 글자 대소문자는 무시하지 않는다.

`InputDelta`는 같은 길이의 입력 벡터에서 바뀐 연속 구간만 저장한다. 길이 변경은 공통 앞뒤를 제외한 구간을 저장한다. 이름 전용 이력은 행/작업 ID와 이름 전후만 저장하며 이름 검증·revision 상한을 먼저 확인한다. 다른 복합 편집과 해당 undo는 현재의 전체 문서 사본/검증 경로를 유지한다. 불변 원장을 공유 구조로 전환한 것은 아니다.

표의 모델 행 삽입/삭제 알림은 정상 전달하고 항목 값 알림만 변경 행 구간으로 묶는다. 기존 항목·변경 없는 행·변경 없는 WBS 트리를 재사용한다. 미계산/오래됨 상태의 Task 캐시와 자원·배정·달력/행 순서/읽기 전용 상태를 비교한다. 유효한 계산 결과나 상태가 바뀌면 날짜와 강조를 다시 채운다. 거절/no-op 입력도 표시 값을 정상화한다.

| 요구사항 | 회귀 근거 |
|---|---|
| FILE-CASE-01 | `file_lifecycle`: 혼합 대소문자/한글/Greek 이름, 물리 파일명·문서 경로, 상대 경로 재열기, 별칭 잠금/덮어쓰기 거절, case-sensitive 파일 분리. `ui_lifecycle`: 저장 대화상자의 실제 `MyUiPlan.jobs` 확인. |
| EDIT-PERF-01 | `EditingPerformanceProbe`, `run-editing-performance-probes.py`, `compare-editing-performance.py`와 원시 전후 JSON. 이름/일반 기간·undo/redo 각각 7표본, 1천/1만·기준선 0/3개. |
| EDIT-PERF-02 | `input_delta_contract`: 떨어진 행/삽입·삭제/빈 배열/모든 입력 필드의 양방향 복원. `undo_contract`: 1만 작업·기준선 3개에서 이름 100회 및 기간 100회의 전체 취소/재실행, 저장 지점·원장·크기/개수 한도·혼합 구조/이름 이력·revision 상한. |
| EDIT-PERF-03 | `editing_performance_ui`: 기존 셀/트리 포인터 유지, 변경 행 알림, 오래된 날짜 제거, no-op 정규화, undo/redo, 선택/스크롤, 정렬/검색/필터 membership, 저장 재열기. 기존 작업 편집·추적·자원·원가·복구·간트 UI 회귀도 유지. |

로컬 Release 전체 CTest **34/34** 통과(최종 UI 변경 후 155.13초), Unicode 정규화 비교 보완 후 `file_lifecycle`도 다시 통과했다. Windows 네이티브 편집 UI 시험과 XLSX 5개/PDF 6개·XML·XER 독립 reader(openpyxl/pypdf/Python XML/TSV/MPXJ 16.10.0 strict)를 통과했다. 새로 컴파일한 코드의 `-Wall -Wextra -Wpedantic` 경고는 없었다. 기본/공수 1천·1만 일정의 전체 결과 해시는 이전 증거와 대조해 네 사례 모두 일치했다. 실제 고객 자료/경쟁 제품 동등성 검증은 아니다.

## 재현과 남은 범위

```powershell
.\scripts\dev.ps1 -TestOnly
# Qt/컴파일러가 PATH에 있는 셸에서
python scripts/run-editing-performance-probes.py --repeats 7
python scripts/run-performance-probes.py --repeats 3
```

각 사례는 별도 프로세스·기본 180초 한도로 실행하고 실패/시간 초과를 정상 표본에 합치지 않는다. CI는 현재 버전에서 100단계 보존을 강제하며 이전 참조에만 `--allow-short-history`를 사용한다. `jobs_build_identity`는 CMake 재설정 없이도 빌드할 때마다 소스/HEAD를 갱신한다.

이 기록 다음 증분에서 `QAbstractTableModel` 전환과 공수 역산·실적/배정 계산의 비동기화·취소를 구현했다. [별도 계약과 검증](model-async-editing.md)을 따른다. 복합 편집/일반 기간 undo의 전체 문서 사본 제거와 아주 큰 기준선/원장은 여전히 후속 범위다. 모든 편집이 상수 시간이 되거나 모든 UI 정지가 사라졌다고 주장하지 않는다. 파일 schema 9와 계산 정책/엔진·기준선/불변 원장·복구 형식은 유지한다.

후속 [대규모 편집 응답성 증분](responsive-editing.md)은 일반 기간의 변경/undo도 한 작업 delta로 처리하고, 정확한 증분 dirty와 공유 worker 요청·모델/WBS 변경 범위 갱신을 추가한다. 이 문서의 전후 수치는 당시 구현에 대한 역사적 기록이다.
