# 대규모 편집 준비·dirty·화면 갱신

2026-10-28 사용자 요청. PRD RESPONSIVE-01~04의 구현 전 계약이다.

Document 내부에서 공유하는 입력은 외부에 수정 가능한 참조로 노출하지 않는다. 요청은 const 스냅샷의 수명을 소유하고 worker에서 독립 Project를 복사/검증한다. 일반 Project/PlanInput과 저장 형식의 값 의미는 바꾸지 않는다. 살아 있는 요청이 있는 동기 수정은 공유 원본에서 분리한다. 최초 열기/명시 저장의 입력 사본 비용은 편집 요청 비용과 구분한다.

정확한 dirty 상태는 저장 시점과 현재 입력의 실제 값 비교에 따른다. 작업 배열 구조가 같을 때 불일치 작업 수와 그 외 입력의 불일치를 분리한다. 단일 이름/일반 기간 및 역방향 명령은 해당 작업의 비교만 갱신한다. 구조·기타 명령은 전체 검증/비교로 재구축한다. 비동기 결과는 캡처한 저장 상태와 원본 상태 각각에 대한 비교를 worker에서 준비해 정상 저장 경합에도 정확히 적용한다. ID/revision/session/취소 검사는 유지한다.

변경 힌트는 원본·결과 revision과 행/범위를 포함하며 마지막 변경에 대한 힌트다. 캐시가 연속 revision을 따라갈 때만 증분 적용하며 여러 변경을 놓치거나 필터/정렬/검색·구조·계산 세대·세션이 바뀌면 전체 동기화한다. 원본 행 번호·안정 ID·읽기 전용·모델 reset 규칙·WBS 기간/미정 합계·선택/스크롤·간트의 의미를 보존한다. 수정하지 않은 상태에서 재요청된 갱신은 생략한다.

단일 이름/일반 기간 변경은 전체 Project 사본과 전체 불변 이력 재검증을 피하되 기존 유효 문서에서 바뀌는 필드의 동일 검증을 수행한다. 공수 역산·관계·달력·구조 변경은 기존 전체 검증 경로를 유지한다. worker 결과의 오래된 입력 해제 비용도 GUI 반영과 구분해 관측하며, 모든 해제/직렬화가 상수 시간이라고 주장하지 않는다.

검증과 수치·전후 참조 커밋·남은 비용은 구현 후 이 문서에 추가한다. 기존 편집 fixture/측정 의미를 유지하고 새 요청/준비/반영 관측은 별도 fixture/필드로 구분한다.
