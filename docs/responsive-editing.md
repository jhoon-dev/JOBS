# 대규모 편집 준비·dirty·화면 갱신

2026-10-28 사용자 요청. PRD RESPONSIVE-01~04를 구현 전 커밋 a592d01/df403de에서 확정한 뒤 f35ca15에 구현했다. 이 문서는 계약과 최종 코드 369051c의 검증 기록이다.

Document 내부에서 공유하는 입력은 외부에 수정 가능한 참조로 노출하지 않는다. 요청은 const 스냅샷의 수명을 소유하고 worker에서 독립 Project를 복사/검증한다. 일반 Project/PlanInput과 저장 형식의 값 의미는 바꾸지 않는다. 살아 있는 요청이 있는 동기 수정은 공유 원본에서 분리한다. 최초 열기/명시 저장의 입력 사본 비용은 편집 요청 비용과 구분한다.

정확한 dirty 상태는 저장 시점과 현재 입력의 실제 값 비교에 따른다. 작업 배열 구조가 같을 때 불일치 작업 수와 그 외 입력의 불일치를 분리한다. 단일 이름/일반 기간 및 역방향 명령은 해당 작업의 비교만 갱신한다. 구조·기타 명령은 전체 검증/비교로 재구축한다. 비동기 결과는 캡처한 저장 상태와 원본 상태 각각에 대한 비교를 worker에서 준비해 정상 저장 경합에도 정확히 적용한다. ID/revision/session/취소 검사는 유지한다.

변경 힌트는 원본·결과 revision과 행/범위를 포함하며 마지막 변경에 대한 힌트다. 캐시가 연속 revision을 따라갈 때만 증분 적용하며 여러 변경을 놓치거나 필터/정렬/검색·구조·계산 세대·세션이 바뀌면 전체 동기화한다. 원본 행 번호·안정 ID·읽기 전용·모델 reset 규칙·WBS 기간/미정 합계·선택/스크롤·간트의 의미를 보존한다. 수정하지 않은 상태에서 재요청된 갱신은 생략한다.

단일 이름/일반 기간 변경은 전체 Project 사본과 전체 불변 이력 재검증을 피하되 기존 유효 문서에서 바뀌는 필드의 동일 검증을 수행한다. 공수 역산·관계·달력·구조 변경은 기존 전체 검증 경로를 유지한다. worker 결과의 오래된 입력 해제 비용도 GUI 반영과 구분해 관측하며, 모든 해제/직렬화가 상수 시간이라고 주장하지 않는다.

검증과 수치·전후 참조 커밋·남은 비용은 구현 후 이 문서에 추가한다. 기존 편집 fixture/측정 의미를 유지하고 새 요청/준비/반영 관측은 별도 fixture/필드로 구분한다.

## 구현

구현은 Document 내부의 `ProjectState`가 Project 값을 소유하며 요청에는 같은 읽기 전용 상태의 소유권만 전달한다. 기존 `Project`/`PlanInput`의 std::vector 및 값 복사 의미는 그대로다. worker는 요청 원본에서 독립 사본을 만들고 결과 입력·이력·dirty 비교 상태를 준비한다. 수명이 보장되는 owning snapshot과 달리 `project()`의 빌린 참조는 다음 문서 변경까지만 사용한다. 동기 수정 시 다른 소유자가 있으면 먼저 분리하며, Document 자체의 쓰기/요청 캡처는 소유 UI 스레드에서 수행한다.

공수 편집 외에도 F9 일정 계산·공수 미리보기·기준선 준비가 읽기 전용 스냅샷을 사용한다. 자동복구는 입력 소유권과 경로/지문/저장 revision/시각을 함께 고정하는 요청을 만들고 큰 RecoverySnapshot은 worker에서 만든다. 디스크 쓰기 전 요청의 원본 참조를 해제한다. worker는 live Document나 위젯을 읽지 않는다.

저장 값과 비교해 배열 크기/ID 순서가 같은지를 확인하고 불일치 작업 수와 나머지 입력 차이를 분리한다. 이름과 일반 기간은 변경된 작업만 비교하고, 단일 작업 값/이름 delta로 undo/redo한다. 범위·작업 유형 규칙은 유효 문서의 변경 필드에 대해 동일하게 검증한다. 공수 역산·관계/달력·구조 및 불변 기록은 기존 전체 검증을 따른다. revision은 입력 동일성 비교에서 제외한다. 이력에서 저장 시점이 밀려나도 비교 상태는 유지한다.

비동기 결과는 요청 당시 저장 입력과 원본 입력 각각에 대한 정확한 dirty 상태를 준비한다. GUI에서 같은 저장 소유권이면 전자를, 요청 중 정상 저장이 원본 revision을 저장했다면 후자를 반영한다. 저장 객체의 주소 재사용을 막기 위해 비교 대상 소유권을 유지한다. 독립 저장/재열기/복구는 세션 검사로 거절한다. 반영 후 수행하는 dirty bookkeeping은 취소로 중간 이탈하지 않고, worker의 전체 비교 뒤 및 GUI 반영 직전 취소 검사는 유지한다.

준비 결과의 이전 입력/사용하지 않은 제안 입력은 GUI 완료 경로에서 소유권을 꺼내 QtConcurrent 작업으로 해제한다. 취소·오래된 결과·반영 알림 중 창 파괴에도 동일하게 수명을 지킨다. 모든 객체 해제가 항상 GUI 밖이라는 주장은 하지 않는다.

모델의 증분 힌트는 직전/현재 revision, 행, 이름 전용 여부다. 현재 보기·세션·계산 세대가 같고 연속 변경일 때 한 작업만 동기화한다. 메인 창은 같은 조건에서 보기 매핑/선택 재설정·기준선 선택 목록·트리/간트 재구성을 생략하고 WBS의 알려진 기간/미정 수를 해당 작업 차이로 조정한다. 진단의 관련 작업 탐색처럼 데이터 변화 없이 선택을 바꾸는 명령은 명시적으로 캐시를 무효화한다. 필터/정렬/검색, 구조, 계산 실효화/완료, 놓친 revision은 전체 갱신을 사용한다.

## 검증 구성과 재현

`responsive_document_contract`는 1만 작업/기준선 3개에서 소유 스냅샷의 동일 주소 캡처와 수정/재열기 후 입력 격리, 원래 값 재입력·기간 미정/0/양수·undo/redo·분기/이력 소진·독립 저장을 전체 Project 값 비교 oracle과 대조한다. 일반 변경의 dirty 작업 비교는 최대 2개, 비동기 GUI 반영은 0개임을 검사한다. 준비 중 정상 저장으로 저장 지점이 바뀐 경우와 자동복구 요청 뒤 원본 편집도 검사한다.

`responsive_editing_ui`는 1만 작업/기준선 3개에서 마지막 행의 이름/기간·undo/redo가 모델 작업 1개만 방문하고 reset·기준선 목록 reset 없이 선택/스크롤과 WBS 합계를 보존하는지 검사한다. 검색은 기존 180ms debounce 완료를 기다린 뒤 검사한다. 검색으로 행이 사라짐, 계산 실효화, 놓친 revision에는 전체 동기화가 수행되는지 확인한다. 기존 제약/진단 탐색·공수·복구 및 전체 UI 회귀를 유지해 CTest는 39개다.

전후 참조 `0645867`은 기능 변경 전의 기존 모델/비동기 구현에 새 단계 측정 도구만 추가한 커밋이다. `jobs-responsive-phases-v1` fixture는 1천/1만 공수 작업·기준선 0/3개에서 요청 생성/worker 준비/Document GUI 반영을 각각 3회 관측하고 성공·공수 보존·undo 저장 지점을 검증한다. `jobs-perf-editing-v1`의 기존 셀 편집/undo 측정 의미는 유지하며 CI에서 같은 실행기의 이전 버전과 비교한다.

## 남은 비용

GUI의 이름/일반 기간 처리에서도 Task 자체와 그 안의 관계/분할 자료 복사는 바뀐 한 작업 크기에 비례한다. 살아 있는 스냅샷과 겹치는 동기 수정은 현재 Project 전체를 분리할 수 있다. 최초 유효 일정의 실효화, 계산 완료, 보기·구조 변경, 복합 명령과 그 undo의 전체 검증/비교·보고서 준비, 최초 열기와 명시 저장/직렬화에는 O(N) 또는 큰 입력 비용이 남는다. 스냅샷 공유는 전체 메모리 사용을 상수화하는 영속 자료구조가 아니다. 단계 관측의 GUI 반영은 화면 갱신/명시 파일 I/O/측정에서 제어한 결과 해제/실제 OS 표시 완료를 포함하지 않는다. 화면 응답은 기존 셀 이벤트 측정과 네이티브 heartbeat/상태 검사로 별도 확인한다.

개발 중 C++20에서 제거된 shared_ptr::unique()를 MSVC/Clang CI가 검출해 use_count()로 수정했다. 최초 전체 회귀의 제약 진단 탐색 실패는 데이터가 같더라도 선택 요청을 처리하도록 갱신 캐시를 무효화해 해결했다. 새 검색 검사는 기존 debounce 대기를 반영했다. 반영 뒤 dirty bookkeeping의 중도 취소를 막는 회귀도 추가했다. 위 완료 판정은 이 수정을 포함한 최종 코드에 대한 것이다.
