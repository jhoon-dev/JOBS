# 작업 표 모델과 비동기 편집 계산

2026-10-27 사용자 요청. PRD MODEL-01, ASYNC-EDIT-01~03, MODEL-PERF-01을 구현 전 커밋 `d4745c7`에 정의했고 제품 구현은 `8906677`에 반영했다. 아래에는 구현 계약과 2026-10-28 검증 기록을 함께 보존한다.

기본 작업 표는 QAbstractTableModel의 행/열/역할로 데이터를 제공하고 QTableView가 필요한 셀만 그린다. 표시는 현재 보기의 프로젝트 원본 행/안정 ID를 따른다. 일반 수정은 값 변경 알림, 구조/보기 순서/문서 세션 변경은 reset으로 알린다. 모델은 표시용 계획/결과를 소유하며 live 문서가 교체되어도 잘못된 포인터를 사용하지 않는다. 기존 입력 3열과 나머지 읽기 전용 열, 경고 색/툴팁·선택·클립보드·간트 의미를 보존한다. 보조 대화상자의 작은 표는 이번 전환 대상이 아니다.

공수 역산과 실적/배정 편집은 문서가 만든 봉인된 요청을 worker에 이동한다. worker는 독립 문서에서 기존 명령·검증·변경분 이력 생성을 수행하고 준비된 결과를 돌려준다. 파일 I/O와 live Document/Qt 객체 접근을 금지한다. 실적 ID는 요청 시 발급하며 취소된 ID를 재사용하지 않는다. 결과는 원본 ID/revision/session과 취소를 확인하고 GUI에서 입력과 이력을 한 번에 반영한다. no-op은 revision/redo를 바꾸지 않는다. 복합 계산의 준비/검증은 worker에 있지만 요청의 초기 입력 사본 생성과 최종 dirty 비교/표시 갱신은 GUI에서 수행하므로 비용을 별도 확인한다.

진행/취소는 기존 CalculationControl의 협력 체크포인트를 사용한다. 취소 예외를 충돌/실패로 바꾸지 않는다. 대화상자는 적용 중 초안을 잠시 잠그고 취소 후 다시 수정/적용할 수 있다. 창 닫기 취소는 이미 적용된 입력을 보존한다. 미반영 요청의 취소/오류/문서 세션 변경은 원본 파일·승인·제출 원장·dirty·revision·undo/redo를 바꾸지 않는다. 성공한 일반 편집은 한 undo이며 실적은 append-only 경계다.

활성 셀 확정 뒤 저장/계산/보고/내비게이션은 pending 결과의 성공/no-op 뒤 계속한다. 취소/오류/다른 문서 변경이면 대기 명령을 폐기한다. 새 편집 요청은 이전 요청을 취소하고 최신 하나만 대기한다. 다른 직접 문서 변경은 오래된 요청을 무효화한다. 수명 종료에서는 worker를 강제 종료하거나 GUI에서 join하지 않고 취소를 요청하며 callback의 위젯 수명을 확인한다.

공수 미리보기는 별도 worker에서 계획과 선택 작업 기간/공수를 계산한다. 새 값을 입력한 뒤 도착한 미리보기로 사용자 초안을 덮어쓰지 않는다. 미리보기 취소/대화상자 종료는 입력 변경이 아니다. 실적 예측 결과의 WBS 기간 표시는 worker에서 이미 구한 계획 날짜를 사용해 GUI 전체 계획 재계산을 피한다. 중간 표시 데이터는 파일/기준선/원장에 직렬화하지 않는다.

검증은 모델 tester·14열 값/역할·readonly·normal edit reset 0·보기/세션 reset과 선택 ID, 기존 전체 UI 및 독립 파일 reader, sealed 결과의 성공/취소/오류/no-op/중복/오래된 세션, 사전/실행 중/완료 직전 취소와 큰 공수 입력의 heartbeat를 포함한다. wall-clock 임계값으로 일반 성능 우월성을 판정하지 않으며 입력/결과 해시와 원시 표본을 남긴다.

CI의 같은 실행기 전후 참조는 이번 전환 전 검증 커밋 `d9270cdf8c8fa5f9b7ee778be22a8f8b311a8150`다. 앞선 변경분 undo 증분의 `3570d28` 대비 기록은 [편집 성능 계약](editing-performance.md)과 해당 과거 CI에 보존한다. 현재 비교는 모델 전환 직전과의 차이이며 기존 100단계 이력을 모두 유지한다.

## 사용과 검증

기본 작업 표의 입력 방식은 동일하다. 고정 공수 기간 셀·붙여넣기·간트와 프로젝트 메뉴의 공수 적용, 실적 저장, 자원 배정 적용은 계산을 요청한 뒤 화면 제어를 돌려준다. 툴바의 **편집 계산 취소** 또는 대화상자의 **계산 취소**로 중단한다. 공수 창은 별도의 **미리보기 취소**를 제공한다. 취소 후 입력값은 대화상자에 남으며 재적용할 수 있다. pending 중 실행 취소/다시 실행은 먼저 요청을 취소한다. 저장·F9·보고·복구/문서 전환은 편집 성공 뒤 진행하고 편집을 취소하면 대기 명령도 폐기한다.

| 계약 | 주요 증거 |

| MODEL-01 | `task_table_model_contract`: QAbstractItemModelTester Fatal, 14열·역할·편집 권한·표시/툴팁·foreign index·안정 ID·일반 변경 reset 0·세션 교체. 기존 표/간트/검색/정렬/TSV UI 회귀를 모델 API로 전환. |

| ASYNC-EDIT-02 | `prepared_edit_contract`와 UI: 사전/실행 중/완료 후 GUI 반영 전 취소, 오류/no-op/1회 반영, revision/session 경합, 동일 ID/revision 재열기, 실적 정정·불변 이력과 일반 편집 한 undo. pending 중 및 결과 반영 알림 중 창 파괴. |

로컬 Windows 11 26H2 / Qt 6.8.3 / MinGW GCC 13.1.0 Release에서 전체 **37/37** CTest를 통과했다(126.51초). 새 최종 화면 캡처 시험도 네이티브 `windows` 플랫폼에서 통과했다. XLSX 5개/PDF 6개와 Project XML, XER TSV/MPXJ 16.10.0의 독립 reader를 통과했다. 1천/1만 기본·공수 일정 네 사례 모두 이전 검증의 전체 `TaskSchedule` SHA-256과 일치했다. 파일 schema 9와 계산 정책/엔진은 유지한다.

[원시 로컬 증거](validation/model-async-2026-10-28/)에 CTest 로그, JSON 표본/소스 식별, 해시 비교와 네이티브 PNG를 보존한다. 셀 측정은 깨끗한 `8906677`, 최종 네이티브 캡처는 `2e6d31c+dirty`다. dirty 항목은 문서/검증 증거이며 제품 소스 해시는 JSON에 보존한다. 구현 이후 커밋은 시험의 빌드 식별·최종 유효 화면·네이티브 동기화와 CI의 컴파일 병렬 수 제한을 보강했다. 네이티브 캡처 중에는 다른 GUI 시험을 동시에 실행하지 않는다. 초기 로컬 실행과 CI `40527937202`의 Windows 네이티브 붙여넣기 단계는 시험 타이밍 가정으로 실패했다. OS 클립보드 값/액션 활성화를 기다리도록 하고, 짧은 전진 단계만 샘플링하던 UI 취소 시험을 달력/전진/후진의 실제 진행으로 보강했다. 코어의 명시적 전진 단계 취소 시험과 완료 직전 취소 시험은 유지한다. 이후 화면 없는 Qt 실행과 네이티브 Windows 2회 연속 실행을 통과했으며 아래 표본은 최종 단독 실행에서 얻었다.

재현은 Qt/컴파일러가 PATH에 있는 셸에서 다음과 같다.

```powershell
ctest --test-dir build --output-on-failure
python scripts/capture-model-async-ui.py build
python scripts/run-editing-performance-probes.py --repeats 7
python scripts/run-performance-probes.py --repeats 3
```

초기 요청의 Project 사본과 최종 dirty 비교·모델 동기화·보기 정렬·WBS/간트 갱신은 GUI에서 수행한다. 복합 편집의 worker 내부에도 기존 전체 사본/검증이 있다. 이번 증분은 모든 문서 데이터를 공유 구조로 바꾸거나 모든 편집을 상수 시간으로 만드는 작업은 아니다. 취소는 협력 체크포인트 방식이며 실행 중인 OS 파일 저장을 강제 중단하지 않는다.


## Windows/MSVC와 macOS CI 완료 기록

최종 코드 `2e6d31c`의 [CI 실행 40531122729](https://github.com/jhoon-dev/JOBS/actions/runs/40531122729)에서 두 플랫폼 모두 **37/37** 회귀·독립 XLSX/PDF/XML/XER reader·네이티브 모델/비동기 편집·교환 대화상자 검사를 통과했다. CTest는 Windows 61.69초, macOS 47.89초였다. 아래 값은 각 OS의 같은 실행기에서 `d9270cd` → `2e6d31c`를 같은 Qt/컴파일러/Release 설정으로 각각 7회 측정한 중앙값이다.

모든 전후 사례는 undo 100단계를 유지했다. 이력 추정량도 OS별로 전후 동일하며 Windows 78,170 bytes, macOS 66,970 bytes다. 이 추정은 C++ 객체 크기를 포함하므로 OS/표준 라이브러리별 차이가 있으며 프로세스 메모리 측정이 아니다. Windows의 일반 셀 편집은 대체로 비슷하며 일부 1천 사례는 느려졌다. macOS는 기준선 없는 1만 사례에서 관측 개선이 컸지만 기준선 3개 사례의 차이는 작았다. 이 표는 보편적 지연 보장이나 통계적 유의성 판정이 아니다.

CI의 1만 공수 작업 네이티브 관측은 Windows 요청 반환 3.57ms / 성공 완료 566.71ms, macOS 4.90ms / 543.99ms였다. 두 OS에서 계산 중 heartbeat와 취소/재시도 검사를 통과했다. 각 JSON은 단일 시험 관측 범위와 타이머 간격의 한계를 명시한다. CI에서도 일정 네 사례의 전체 결과 해시가 각 OS에서 이전 검증과 동일함을 별도로 확인했다.

[원시 CI 전후 표본과 관측](validation/model-async-2026-10-28/)의 `ci-Windows/`, `ci-macOS/`, `ci-results.json`에서 빌드 식별·표본·해시·완료 상태를 확인한다.

후속 RESPONSIVE-01~04 증분에서 이 기록 당시 UI에 남았던 요청의 큰 입력 복사와 전체 dirty 비교를 worker로 이동하고, 일반 기간의 단일 작업 delta 및 연속 변경의 모델/WBS 증분 갱신을 추가했다. 이전 버전의 원시 관측과 한계는 이 문서에 보존하며 최신 계약·검증은 [대규모 편집 응답성](responsive-editing.md)을 따른다.
