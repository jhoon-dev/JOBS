# 선행관계·지연/선행 시간·작업 달력

2026-10-26 사용자 요청으로 FS·SS·FF·SF와 부호 있는 근무분 지연, 작업별 달력을 구현했다. 기존 FS0 계산 정책과 승인 기준선은 유지하고 확장 입력에 `native-pdm-taskcal-v1` / `jobs-pdm-1.0`을 사용한다.

## 입력

작업 표의 **선행(행·종류±지연)** 열에 프로젝트 전체의 왼쪽 행 번호를 입력한다. WBS 필터 중에도 전체 행 번호를 사용하며 파일에는 안정 ID를 저장한다.

| 입력 예 | 의미 |
|---|---|
| `1,3` | 1번·3번 작업 완료 후 시작, FS 0 |
| `1SS+2h` | 1번 시작에서 후행 달력 120근무분 뒤 시작 가능 |
| `2FF-30m` | 2번 완료보다 후행 달력 30근무분 앞선 시점 이후 완료 |
| `3SF+1d` | 3번 시작에서 후행 달력 480근무분 뒤부터 완료 가능 |

관계 종류는 대소문자를 구분하지 않는다. 기본 종류는 FS다. `m`은 분, `h`는 60분, `d`는 달력의 일일 길이와 무관한 **480근무분 단위**다. 소수는 정수 분으로 정확히 환산될 때 허용한다. 양수는 지연, 음수는 선행이며 ±5,000,000분 한도다. 한 후행 작업에는 같은 선행 ID를 한 번만 지정한다. 작업 간 여러 종류의 중복 간선은 아직 지원하지 않는다.

**프로젝트 → 작업 달력 등록·편집**에서 이름·근무 요일(월1~일7)·시간대(`09:00-12:00,13:00-18:00`)·휴일을 등록한다. 시간대는 정렬된 비중복 구간이고 끝에 `24:00`을 허용한다. 자정을 넘는 교대는 `00:00-06:00,22:00-24:00`처럼 나누며 같은 주간 패턴이 지정 요일마다 적용된다. 예외일의 대체 근무·계절 패턴·자원 달력은 후속 범위다.

작업을 선택하고 **선택 작업 달력 배정**에서 달력을 고른다. 표의 작업 달력 열과 간트 툴팁에 배정을 표시한다. 기본 배정은 월–금 09–12 / 13–18과 프로젝트 휴일이다. 사용자 달력은 자체 요일·시간대·휴일을 사용하며 프로젝트 휴일을 자동으로 합치지 않는다. 배정된 달력은 삭제할 수 없으며 먼저 작업 배정을 해제해야 한다. 달력 정의 변경·배정·관계 편집은 실행 취소/다시 실행과 자동 복구 대상이다.

## 계산 의미

각 관계는 하한 제약이다. FS는 `후행 시작 ≥ 선행 완료 + 지연`, SS는 시작→시작, FF는 완료→완료, SF는 시작→완료다. 지연은 **후행 작업 달력 근무분**으로 이동하며 0은 선행 endpoint의 현지 시각을 그대로 전달한다. 경과시간 지연이나 선행 달력 선택은 제공하지 않는다. 시작일 이전에 작업을 배치하지 않으며 여러 관계 중 가장 늦은 하한을 적용한다.

기간은 해당 작업 달력의 근무분이다. 비근무 시간·휴일은 기간을 소비하지 않는다. 근무 시작과 완료 경계를 구분하므로 FS0 마일스톤은 선행 작업의 근무 종료 경계에 놓일 수 있다. FF/SF 또는 달력 간 비근무 경계에서는 유효한 완료 시각이 하한보다 빠르지 않도록 **1근무분 단위**에서 올림한다. 따라서 비근무 시각을 가리키는 완료 하한의 첫 해가 다음 근무 구간의 첫 1분일 수 있다. 작업 기간이 같은 경우에도 서로 다른 달력에서 경과기간은 달라진다.

순환은 관계 종류/지연 부호와 관계없이 충돌로 보고 실제 순환 경로를 표시한다. 반복/시간창을 포함한 순환 네트워크의 일반 제약해법은 제공하지 않는다. 기간 미정·참조 오류·20년 내 가용 시간 부족 시 전체 완료일을 확정하지 않는다. 빈/중복 요일, 겹친 시간대, 누락 달력, 잘못된 종류·지연을 거절한다.

정방향 계산은 작업별 달력에 맞는 가장 이른 날짜를 찾는다. 역방향은 공통 프로젝트 완료일 아래에서 후행의 늦은 시작을 위반하지 않는 가장 늦은 시작을 탐색한다. 총여유·자유여유는 **해당 작업 달력의 근무분**이다. 확장 프로필의 early/late 숫자 좌표는 시작일 자정부터의 civil 경과분이며 여유는 별도 근무분이다. 기존 프로필의 숫자 좌표는 기존 기본 달력 누적 근무분으로 유지한다. 저장된 프로필/엔진과 함께 해석해야 한다.

상태일 예측은 실제 시작/완료를 고정하고 상태일 이후 잔여 작업에 네 가지 관계와 작업 달력을 적용한다. 진행 중 작업의 시작 endpoint는 실제 시작이며 완료 endpoint는 잔여 예측 완료다. 실제가 관계를 위반하면 `OUT_OF_SEQUENCE`를 표시하며 날짜를 고치지 않는다. 예측/자원 평준화의 여유·임계는 미산정이다.

## 기존 기능과 파일

- 자원 부하는 각 작업의 실제 근무 구간만 공통 civil 시간축에 예약한다. 점심·휴일·야간 공백은 수요가 아니다. 평준화는 모든 선행 작업이 배치된 뒤 관계별 하한과 작업 달력을 다시 적용하고 자원 가능한 구간을 탐색한다. 탐색 한도는 기본 달력의 근무일 수이며 사용자 교대 일수와 다르다. 최적해 보장은 없다.
- 계획 원가는 같은 근무 구간과 발생일 단가를 사용한다. 균등 고정비는 작업 달력의 근무분에 배분하며 AC는 기존 누적 보고를 유지한다. 기준선 BAC/PV는 당시 입력·달력·계산 정책을 사용한다.
- 기준선 비교는 종류/지연·달력 배정/정의 변경을 구분한다. 작업 편차는 기준선 작업 달력, 프로젝트 전체 완료 편차는 기준선 프로젝트 기본 달력의 근무분이다. 간트 배경 음영은 기본 달력 휴무이며, 작업별 달력은 툴팁에 명시한다. 막대는 전체 시작~완료 범위다.
- 보고서의 계획 일정·선행관계·출처 표에 작업 달력, 관계 종류, 부호 있는 지연 근무분, 달력 정의·배정을 포함한다. XLSX/PDF에도 같은 값을 내보낸다.
- `.jobs`는 **schema 7**이다. schema 1~6은 기존 정책과 승인 결과를 유지해 읽고 새 파일에 저장한다. 원본을 자동 변환하거나 덮어쓰지 않는다. 확장 정책의 입력은 `calendars`, 작업 `calendarId`와 `dependencyRules`를 포함한다. 기존 `predecessors` ID 그래프와 일대일 대응하는 비-FS0 속성만 rules에 저장한다. 구 정책의 입력/기준선에는 확장 필드를 넣지 않는다.
- 자동복구 envelope schema 1은 유지하며 내부 `projectSchema` 6/7을 모두 읽고 새 체크포인트는 7로 기록한다. 불변 기준선/원장 정책, 파일 잠금·해시·원자적 저장·사본 복구 계약을 유지한다.

## 검증

`pdm_calendar_contract`는 네 endpoint 종류·음수/양수 지연·주말/휴일·독립 토요일 달력, 분 단위 전진 탐색과 CPM 여유, 순환/잘못된 달력, 구/신 기준선 재검증, schema 7·schema 6 원본 보존, 복구/실행 취소, 실제 근무 구간의 자원·평준화·원가·예측·보고를 검증한다. `pdm_calendar_ui`는 달력 등록/배정, 표 입력/오류, 실행 취소/재실행, F9 날짜와 간트 출처, 읽기 전용을 검증한다. 전체 CTest는 기존 17개에 두 개를 추가한 19개다. 독립 XLSX/PDF reader로 PDM 보고서의 관계·음수 지연·달력도 확인한다.

대규모 성능·외부 제품과의 숫자 동등성·자원별 달력 교집합·분할 작업·일별 대체 근무는 별도 검증/후속 범위다.

로컬 Windows에서 전체 19개 및 마지막 UI 보완에 대한 PDM/자원 재검증을 통과했다. Windows 네이티브 달력 등록/배정·간트 화면을 확인하고 PDF 6페이지를 렌더링해 표와 출처를 검토했다. 독립 reader는 기존 출력과 PDM 출력을 합한 XLSX 3개/PDF 4개를 검증한다.

후속 작업 날짜 제약/마감·간트 편집은 schema 8 / jobs-pdm-1.1이며 기존 native-pdm-taskcal-v1 결과를 유지한다. [제약·간트 계약](constraints-gantt.md)에 정책과 구 입력 보존 범위를 기록한다.
