# 다중 프로젝트·공유 자원 작업공간

2026-10-28 사용자 승인. MULTI-01~06을 구현 전에 확정한다. 여러 독립 JOBS 문서를 한 프로세스의 별도 창에서 편집하고, 별도 작업공간에서 공유 자원과 통합 부하를 관리한다.

각 창은 자신의 Document·계산/편집 이력·잠금·자동 복구를 사용한다. 동일 경로 중복 열기는 기존 창을 활성화하며, 다른 파일이 동일 documentId를 가진 경우 독립 사본 저장을 안내한다. 프로젝트 이름·작업/자원 ID는 프로젝트 ID와 묶어서 구분한다. 프로젝트를 닫아도 저장된 파일 참조와 공유 연결은 작업공간에 남고, 다시 열거나 명시적으로 작업공간에서 제외할 수 있다. 닫힌 문서를 포함한 전체 정상 결과로 오인하지 않도록 상태를 표시한다.

공유 카탈로그는 별도 Resource 용량/일별 예외와 TaskCalendar 근무 구간/휴일을 갖는다. 자원 연결은 (documentId, resourceId)→공유 ID이며 이름 매칭을 하지 않는다. 종류와 units는 기존 100=1인/장비 단위다. 프로젝트 로컬 capacity와 배정을 자동 덮어쓰지 않고 공유 capacity 대비 초과를 진단한다. 원가와 자원 일정 자체는 각 프로젝트 정책을 유지한다.

통합 계산은 프로젝트별 `calculatePlan` 또는 `calculate` 결과에서 실제 작업 실행 구간을 구한다. legacy 근무분, PDM civil 분, 공수/분할/자원 달력 및 예측 잔여를 공통 civil 날짜/분으로 변환한다. 반개구간 [시작,완료)의 이벤트를 합쳐 겹치는 수요만 더하며 각 일자와 공유 달력 경계에서 용량을 비교한다. 공유 휴무 구간 용량은 0, 근무 구간은 기본/일별 예외 용량이며 미정은 0으로 가정하지 않는다. 전체 일일 peak를 더하는 방식은 사용하지 않는다.

프로젝트별 snapshot과 카탈로그 세대를 고정하고 worker에서 계산한다. 취소/수정/닫기/stale 결과는 부분 반영하지 않는다. 연결 범위·미연결 수·유효/누락 프로젝트·source revision·계획/현재 예측 모드를 화면에 표시한다. 결과에서 원본 프로젝트/작업으로 이동한다. 전역 평준화나 교차 프로젝트 논리를 새로 만들지 않는다.

`.jobsworkspace` schema1은 별도 UTF-8 JSON envelope/checksum이다. 프로젝트 참조·기대 documentId·공유 Resource/달력·연결만 저장한다. 상대 경로를 우선 사용하고 파일별 독립 잠금/저장/ID를 유지한다. 8 MiB, 프로젝트 100개·공유 자원 1,000개·연결 10,000개 한도를 검증하고 알 수 없는 필드/값·중복·잘못된 참조는 거부한다. 저장 전 열린 프로젝트의 입력을 별도 `.jobs`에 저장하도록 안내한다. 생성은 create-only, 기존 저장은 열린 fingerprint 검증과 QSaveFile 교체를 사용한다. 작업공간 열기 시 전체 참조를 검사하고 새 문서 준비 실패 시 기존 창과 카탈로그를 보존한다. 종료 시 저장하지 않은 카탈로그 변경을 확인한다.

구현·조작 방법·수동 기대값 fixture·검증/설치 산출물은 후속 절에 기록한다.

## 사용 방법

파일 메뉴의 **다중 프로젝트·공유 자원…**을 연다. **프로젝트 추가**는 기존 문서를 독립 창으로 열고 **새 프로젝트 창**은 새 문서를 만든다. 각 창에서 작업·자원·실적을 편집하고 저장한다. 동일 파일을 다시 선택하면 기존 창이 앞으로 온다.

**공유 자원·연결** 탭에서 실제 인력/장비를 등록한다. 용량은 백분율이며 `100`은 1명/대, `?`는 미정이다. 공유 근무 요일·시간대·휴일과 날짜별 용량을 설정하고 각 프로젝트의 로컬 자원을 명시적으로 연결한다. 공유 자원을 삭제하면 그 자원으로 향하는 연결도 제거한다.

공유 기본/일별 용량은 `0~10,000,000` 또는 `?`이며 로컬 자원의 상한 `100,000`과 구분한다. 공유 이름은 전체 파일의 8 MiB 제한 안에서 길이와 유니코드 문자를 보존한다. 공유 달력의 근무 구간은 최대 100개, 휴일과 일별 용량 예외는 각각 최대 10,000개다. 입력 시 개수 한도를 검사하며 저장할 실제 JSON도 읽기 검증을 통과한 뒤 원자적으로 교체한다. 검증 실패 시 기존 파일을 보존한다.

**기간별 통합 부하**에서 현재 예측 또는 계획 일정을 선택하고 **통합 부하 계산**을 누른다. 최대 수요, 수요 공수, 과부하 시간, 초과 공수와 가용량 미정 시간을 확인한다. 행의 관련 작업을 선택해 **원본 작업으로 이동**하면 해당 창의 검색·필터를 해제하고 작업을 선택한다. 입력이 바뀌었거나 계산 방식을 바꾼 결과는 다시 계산해야 탐색할 수 있다.

프로젝트를 각각 저장한 후 **작업공간 저장**으로 목록·공유 카탈로그·연결을 함께 보관한다. `.jobsworkspace`만 복사하면 프로젝트 본문은 포함되지 않으므로 참조한 `.jobs` 파일도 함께 옮긴다. **작업공간 열기**는 필요한 파일과 ID·잠금을 모두 확인한 후 창을 추가한다. 먼저 열려 있던 독립 프로젝트는 유지하며 목록에 포함한다. **닫힌 프로젝트 제외**는 문서 파일을 삭제하지 않는다.

## 수동 기대값과 경계

두 프로젝트에서 같은 공유 자원에 각각 100%를 배정한다. 첫 작업이 09:00–10:00, 둘째가 10:00–11:00이면 최대 100%, 과부하 0분이다. 둘째를 09:30–10:30으로 옮기면 최대 200%, 과부하 30분, 초과 공수 0.5시간이다. 공유 용량을 200%로 바꾸면 초과가 없고, `?`로 바꾸면 90분이 가용 미정이다. 같은 날 공유 휴일을 넣으면 0% 용량과 비교한다.

프로젝트별 시작일과 로컬 ID가 달라도 절대 날짜·시간과 프로젝트 ID로 구분한다. 공수 작업은 작업·자원 달력의 교집합, 점심/분할 중단, 상태일 이후 잔여 실행 구간만 사용한다. 보고된 과거 실적을 향후 공유 부하로 재배정하지 않는다. 미연결 자원과 닫힌 프로젝트가 있으면 범위 표시를 확인한다. 이 화면은 공유 부하 진단이며 전역 평준화는 제공하지 않는다.

## 검증과 재현

`shared_resource_intervals`는 수동 기대값과 24개 분 단위 독립 oracle, 프로젝트 ID 범위, 다른 시작일/달력·점심/분할·잔여 공수, 가용 미정/0·휴무·미연결·닫힌 프로젝트와 취소를 검사한다. `workspace_file_contract`는 상대 경로·메모리/파일 디코더 일치·체크섬·버전·알 수 없는 필드·크기·참조·잠금·외부 변경 보호를 검사한다.

2026-10-30 점검 회귀로 긴 유니코드 공유 이름의 저장/재열기, 공유 기본/일별 용량의 미정·0·100,001·10,000,000 경계와 범위 초과 거부, 휴일/예외 개수 경계·초과 거부 및 실패한 저장의 기존 bytes 보존을 검사한다. 통합 부하는 로컬 상한보다 큰 공유 용량/일별 예외에서도 실제 중첩 수요의 과부하를 검산한다.

`multi_project_workspace_ui`는 독립 창·중복 파일/ID·dirty/undo 격리, 저장/재열기와 준비 실패의 원자적 복원, 계산 취소·stale 차단을 검사한다. 입력을 바꾼 직후 새 계산을 시작하고 타이머 갱신을 강제로 발생시켜 최신 계산이 이전 변경 때문에 취소되는 회귀를 막는다. `python scripts/check-workspace-native.py build`는 네이티브 UI에서 같은 계약을 검사하고 실제 Qt 화면을 캡처한다.

파일 접근 없는 `.jobsworkspace` 파서 퍼징은 기존 `.jobs`·XML·XER와 같은 sanitizer 빌드에서 실행한다. [소스 버전별 결과와 설치 산출물](validation/workspace-2026-10-28/README.md)을 따른다.
