# 다중 프로젝트·공유 자원 작업공간

2026-10-28 사용자 승인. MULTI-01~06을 구현 전에 확정한다. 여러 독립 JOBS 문서를 한 프로세스의 별도 창에서 편집하고, 별도 작업공간에서 공유 자원과 통합 부하를 관리한다.

각 창은 자신의 Document·계산/편집 이력·잠금·자동 복구를 사용한다. 동일 경로 중복 열기는 기존 창을 활성화하며, 다른 파일이 동일 documentId를 가진 경우 독립 사본 저장을 안내한다. 프로젝트 이름·작업/자원 ID는 프로젝트 ID와 묶어서 구분한다. 프로젝트를 닫아도 저장된 파일 참조와 공유 연결은 작업공간에 남고, 다시 열거나 명시적으로 작업공간에서 제외할 수 있다. 닫힌 문서를 포함한 전체 정상 결과로 오인하지 않도록 상태를 표시한다.

공유 카탈로그는 별도 Resource 용량/일별 예외와 TaskCalendar 근무 구간/휴일을 갖는다. 자원 연결은 (documentId, resourceId)→공유 ID이며 이름 매칭을 하지 않는다. 종류와 units는 기존 100=1인/장비 단위다. 프로젝트 로컬 capacity와 배정을 자동 덮어쓰지 않고 공유 capacity 대비 초과를 진단한다. 원가와 자원 일정 자체는 각 프로젝트 정책을 유지한다.

통합 계산은 프로젝트별 `calculatePlan` 또는 `calculate` 결과에서 실제 작업 실행 구간을 구한다. legacy 근무분, PDM civil 분, 공수/분할/자원 달력 및 예측 잔여를 공통 civil 날짜/분으로 변환한다. 반개구간 [시작,완료)의 이벤트를 합쳐 겹치는 수요만 더하며 각 일자와 공유 달력 경계에서 용량을 비교한다. 공유 휴무 구간 용량은 0, 근무 구간은 기본/일별 예외 용량이며 미정은 0으로 가정하지 않는다. 전체 일일 peak를 더하는 방식은 사용하지 않는다.

프로젝트별 snapshot과 카탈로그 세대를 고정하고 worker에서 계산한다. 취소/수정/닫기/stale 결과는 부분 반영하지 않는다. 연결 범위·미연결 수·유효/누락 프로젝트·source revision·계획/현재 예측 모드를 화면에 표시한다. 결과에서 원본 프로젝트/작업으로 이동한다. 전역 평준화나 교차 프로젝트 논리를 새로 만들지 않는다.

`.jobsworkspace` schema1은 별도 UTF-8 JSON envelope/checksum이다. 프로젝트 참조·기대 documentId·공유 Resource/달력·연결만 저장한다. 상대 경로를 우선 사용하고 파일별 독립 잠금/저장/ID를 유지한다. 8 MiB, 프로젝트 100개·공유 자원 1,000개·연결 10,000개 한도를 검증하고 알 수 없는 필드/값·중복·잘못된 참조는 거부한다. 저장 전 열린 프로젝트의 입력을 별도 `.jobs`에 저장하도록 안내한다. 생성은 create-only, 기존 저장은 열린 fingerprint 검증과 QSaveFile 교체를 사용한다. 작업공간 열기 시 전체 참조를 검사하고 새 문서 준비 실패 시 기존 창과 카탈로그를 보존한다. 종료 시 저장하지 않은 카탈로그 변경을 확인한다.

구현·조작 방법·수동 기대값 fixture·검증/설치 산출물은 후속 절에 기록한다.
