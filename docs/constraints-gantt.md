# 작업 제약·마감일·일정 충돌·간트 편집

2026-10-26 사용자 후속 요청으로 날짜 제약, 마감일 경고, 원인별 일정 진단과 간트 드래그 편집을 구현했다. 새 입력은 `native-pdm-constraints-v1` / `jobs-pdm-1.1`로 계산한다. 기존 FS0/PDM 정책의 승인 결과를 재해석하지 않는다.

## 제약과 마감일 설정

작업을 선택하고 **프로젝트 → 선택 작업 제약·마감일**에서 설정한다. 날짜는 현지 civil `YYYY-MM-DD HH:mm`이며 시간대 변환을 하지 않는다. 적용하면 전체 선행 그래프를 백그라운드에서 다시 계산한다. 제약 종류·시각·마감일을 한 번의 편집으로 저장하고 실행 취소할 수 있다. 읽기 전용 문서는 조회만 가능하다.

| 종류 | 날짜 의미 |
|---|---|
| ASAP 가능한 빨리 | 프로젝트 시작·선행관계·작업 달력을 만족하는 가장 이른 배치. 제약 시각 없음 |
| ALAP 가능한 늦게 | 현재 프로젝트 완료일 안에서 배치된 후행 작업을 늦추지 않는 가장 늦은 배치. 제약 시각 없음 |
| SNET 시작 이후 | 시작 ≥ 제약 시각 |
| SNLT 시작 이전 | 시작 ≤ 제약 시각 |
| FNET 완료 이후 | 완료 ≥ 제약 시각 |
| FNLT 완료 이전 | 완료 ≤ 제약 시각 |
| MSO 시작 고정 | 시작 = 제약 시각 |
| MFO 완료 고정 | 완료 = 제약 시각 |

이후/이전은 경계를 포함한다. 각 작업은 날짜 제약 하나와 별도 마감일 하나를 가진다. ASAP/ALAP에는 날짜를 저장하지 않고 나머지 종류에는 유효한 날짜를 요구한다. 제약 해제는 ASAP, 마감 해제는 마감일 빈칸으로 한다. 작업 달력·기간·FS/SS/FF/SF와 지연/선행을 함께 적용한다.

SNET/FNET의 하한은 작업 달력의 다음 가용 경계로 정렬한다. 상한을 만족할 수 없으면 충돌이다. 고정 시각은 작업 달력의 정확한 시작/완료 경계여야 한다. 점심이나 휴무의 MSO/MFO를 무음으로 바꾸지 않는다. 프로젝트 시작 이전에 배치하지 않으며 20년 가용 시간 범위를 유지한다. ALAP 체인은 역순으로 배치한다. 별도의 프로젝트 완료 고정일, 중복 날짜 제약, 분할 작업·일반 순환 제약 해법은 후속 범위다.

**마감일은 소프트 경고 기준**이다. 완료 civil 시각이 마감보다 늦으면 `DEADLINE_MISSED`를 표시하고 간트 마감 표식과 표 셀을 강조한다. 일정을 강제로 옮기거나 계산 전체를 실패시키지 않는다. CPM 총여유와 구분한 **마감 여유**는 작업 달력에서 `마감 근무분 - 완료 근무분`이다. 음수 값을 보고서에 숫자로 내보낸다. 휴무 시간만 지나면 0근무분이어도 civil 시각 초과 경고를 유지한다. 마감이 달력 계산 범위 밖이면 마감 여유는 미정이다. 마감일은 CPM 총여유를 변경하지 않는다.

## 일정 충돌 진단

**프로젝트 → 일정 충돌 진단**은 현재 입력 revision의 별도 스냅샷을 비동기로 계산한다. 충돌/입력, 경고, 정보를 구분하고 코드·원인·관련 날짜·작업을 표시한다. 행을 선택한 뒤 **관련 작업 선택**으로 해당 작업으로 이동한다. 현재 WBS 밖 작업도 전체 프로젝트 ID로 찾아 선택한다. 진단을 본 뒤 문서가 바뀌면 오래된 revision의 선택을 적용하지 않는다.

- `CONSTRAINT_CONFLICT`: 선행관계/달력/상태일로 필요한 시작·완료와 날짜 제약이 충돌. 작업과 driving 선행 ID, 요구 제약 시각과 계산 날짜를 표시한다.
- `CONSTRAINT_CALENDAR`: 고정 시각이 해당 작업 달력에 없거나 제약 날짜의 가용 경계를 계산할 수 없음. 달력/날짜 수정을 안내한다.
- `CONSTRAINT_HORIZON`: 작업 기간/배치가 계산 범위를 초과. 가능한 경우 관련 작업 ID를 표시한다.
- 기존 기간 미정·누락/자기 선행·실제 순환 경로, `OUT_OF_SEQUENCE`도 함께 확인한다.

하드 제약 충돌 시 프로젝트 완료일을 확정하지 않고 계획 막대를 표시하지 않는다. 원래 입력은 유지하므로 제약·선행·기간·달력을 수정하거나 실행 취소할 수 있다. 현재 작업 목록에서 관련 작업 이름을 강조하며 원인 전체는 진단 창/툴팁에 보존한다. 부분 날짜를 정상 일정이나 계획 원가로 오표시하지 않는다.

실적 예측은 실제 시작/완료를 고정한다. 시작한 작업의 시작 제약은 실제 시작과 비교하고, 잔여 재개에 다시 강제하지 않는다. 완료 제약은 잔여 기간을 기준으로 적용한다. 실제/예측이 하드 제약을 위반하면 완료일을 확정하지 않으며 실제 날짜를 고치지 않는다. ALAP은 계획 배치에 적용하고 상태일 예측은 기존 retained remaining의 가장 이른 재개를 사용하며 이 차이를 진단한다. 예측 여유/임계는 미산정이다.

자원 평준화도 날짜 제약을 재검증한다. 자원 부족으로 MSO/MFO나 상한을 지켜 배치할 수 없으면 충돌로 반환하며 부분 결과를 확정하지 않는다. 소프트 마감 초과는 경고로 남긴다. 저장 시나리오는 `serial-no-split-constrained-v1`과 당시 입력/원장을 보존한다.

## 간트 드래그

- 최신 유효한 **계획**의 막대를 좌우로 끌면 날짜를 이동한다. ASAP/ALAP은 SNET으로 바꾸고, 날짜 제약이 있으면 종류를 유지하며 대응하는 시작 또는 완료 제약 날짜를 옮긴다. 마감일·기간·선행 ID·달력·실적은 유지한다. SNLT/FNLT처럼 상한을 옮긴 경우 실제 배치는 더 이를 수 있다.
- 선택한 막대의 **오른쪽 끝** 또는 **Shift+드래그**는 작업 달력의 근무 기간을 바꾼다. 기존 제약/마감일을 유지하므로 MFO 등의 재계산 결과는 시작도 바뀔 수 있다. 왼쪽 끝 resize, 자원 배정률 조정, 관계 생성 드래그는 제공하지 않는다.
- 드래그 중 윤곽과 날짜·근무분·변경할 제약을 미리 표시한다. 화면 이동량을 civil 15분 단위로 반올림한 뒤 작업 달력에 정렬한다. 일/주 배율과 가로 스크롤에서도 같은 좌표/안정 ID 규칙을 사용한다. 휴일을 건너뛰어 표시 위치가 바뀔 수 있다.
- **Esc**는 입력을 변경하지 않고 취소한다. 클릭이나 같은 결과의 이동은 revision/이력을 늘리지 않는다. 잘못된 날짜·0 이하 resize는 상태줄에 표시하고 적용하지 않는다. 마일스톤은 이동할 수 있으며 resize는 기간 표에서 한다.
- 놓으면 한 번의 문서 편집으로 저장한 뒤 전체 일정을 자동 재계산한다. 후행 작업은 FS/SS/FF/SF와 지연에 따라 다시 배치된다. 제약 충돌은 진단으로 전환한다. 미리보기에서 여러 작업을 몰래 고정하지 않는다. 실행 취소/다시 실행은 새 revision을 사용하며 다시 계산할 수 있다.
- 읽기 전용, 오래된/불완전/충돌 일정, 상태일 예측, 실제 시작 이력이 있는 작업은 드래그 대상이 아니다. 실제 시작 기록은 상태일을 해제해도 보호한다. 미리보기 도중 문서/계산/뷰가 교체되면 취소하거나 revision 검증으로 거절한다. OS 창 비활성화·숨김과 배율/기준선 재구성도 미리보기를 취소한다.

## 저장과 보고

`.jobs` **schema 8**에 작업 `constraintType`, nullable `constraintAt`·`deadlineAt`를 기록한다. 확장 프로필에만 필드를 넣으며 이전 프로필 입력에는 생략한다. schema 1~7은 기존 계산 정책/승인 결과로 읽고 원본 보존 SaveAs를 요구한다. 복구 envelope schema 1은 내부 projectSchema 6/7/8을 읽고 새 복구본은 8을 쓴다. 제약/마감/드래그 변경은 자동 복구와 일반 실행 취소 범위다. 불변 승인·제출 원장은 유지한다.

기준선은 날짜 제약과 마감을 포함한 입력/계산 결과를 고정하며 변경 비교에 제약/마감 변경을 표시한다. 보고서는 새 프로필에서 **작업 제약과 마감** 표를 더해 종류·시각·마감·활성 완료·마감 여유·상태를 제공한다. 진단 표에 충돌/경고와 원인 ID를 포함하고 XLSX/PDF에 같은 값을 내보낸다. 구 프로필의 14개 표는 유지하며 새 프로필은 15개다. 실제원가는 기존 보고 원장을 사용하며 날짜 드래그로 다시 만들지 않는다.

## 검증

`constraint_contract`는 8종 제약·ALAP 체인, 상한/고정/달력·FS 충돌과 원인 날짜/ID, 소프트 마감과 음수 여유, 실제 날짜 보존, 자원 평준화, guarded atomic drag/실행 취소, schema 8/구 정책 원본·복구·보고를 검증한다. `constraint_gantt_ui`는 실제 viewport 마우스 이벤트로 날짜 이동·기간·후행 전파·Esc·오래된 드래그 차단·일/주 배율·예측/읽기 전용을 검증하고, 경고/하드 충돌 탐색과 수정 후 정상 복귀를 확인한다. 기존 19개에 두 개를 추가해 전체 CTest 21개다.

독립 reader 검증은 XLSX 4개/PDF 5개이며 제약 종류·날짜·음수 마감 여유·마감 상태를 재확인한다. Windows 네이티브 제약/진단/간트 화면과 PDF 렌더링도 검토한다. 대형 프로젝트 드래그 반응성·보조기술·외부 상용 도구와의 숫자 동등성은 별도 검증 게이트다.
