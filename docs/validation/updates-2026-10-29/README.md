# 시작 알림·수동 업데이트 검증

2026-10-29. UPDATE-01~06은 `a9047f3`에서 구현 전에 PRD에 추가했다. 제품 검증 대상은 `a0c97697a9e48fd73474d7ff2d9f20622ddbc17f`이며 앱 버전은 0.2.0, 개발 MSIX는 1.0.2.0이다. [기능·운영 계약](../../application-updates.md)을 따른다.

설정 → 업데이트…에서 지금 확인, 확인/다운로드 취소, 시작 시 자동 확인 설정을 사용할 수 있다. 자동 확인은 한 프로세스에서 한 번, UI가 열린 뒤 비동기로 실행된다. 새 버전은 작업을 막지 않는 배너로 안내한다. Store판은 StoreContext로 확인하고 Microsoft Store에서 업데이트한다. 등록된 Windows 일반 설치판은 정식 GitHub Release의 설치기를 내려받아 크기·SHA-256을 검증한 뒤 저장 확인과 Windows 보안 처리를 거쳐 실행한다. 개발 실행과 자동 검증이 불가능한 Release는 릴리스 페이지를 안내한다.

## 검증 범위

- 로컬 MinGW Release의 CTest 51개가 모두 통과했다(136.22초). 새 `application_updates`의 Qt Test 결과는 초기화/종료를 포함해 18개 통과이며 가짜 네트워크와 Store 응답을 사용한다. 공개 서버나 실제 계정을 테스트 응답으로 바꾸지 않는다.
- 새 버전·동일/이전 버전·미게시·오프라인·시간 초과·중복 확인·취소 후 늦은 응답, 설정 유지와 여러 창의 단일 시작 확인을 검사한다. 다운로드 digest/크기/변조/리디렉션·취소, Store 경로 분리, 저장 취소·계산 중 설치 지연·실행 실패 시 창 유지, 설치 승인 중 모달 보호도 검사한다.
- 설치 여부 조회만으로 Windows 제거 등록 키가 생성되지 않는 회귀 검사를 추가했다. 파일 경로의 대소문자는 변경하지 않는다.
- [Windows 설치 검사](update-install-result.json)는 실행 중인 다른 프로세스의 교체 거부, 이전 PID 종료 대기, 등록된 사용자 지정 설치 경로 유지, 업데이트 중 설정·외부 프로젝트 유지, 전체 제거 후 앱 상태 정리를 통과했다. **동일 빌드 재설치로 설치 전환을 검증**했으며 공개된 구버전에서 신버전으로 올라가는 온라인 E2E와 구분한다.
- [MSIX 검사](lifecycle.json)는 실제 package identity 아래 생산 앱 실행과 생성/저장/열기·계산·undo·작업공간·복구, 1.0.2.0 → 1.0.3.0 개발 패키지 갱신과 제거를 통과했다. 업데이트 설정 UI와 Store 미연결 개발 패키지 처리도 검사한다.

정적 분석·Windows/macOS 회귀·ASan/UBSan·파서 퍼징의 최종 상태는 [검증 요약](verification.json)과 [CI 실행 기록](ci-runs.json)에 보존한다. 네이티브 설치·업데이트 검사는 사용자의 설치 상태를 바꾸지 않는 폐기 가능한 Windows CI에서 수행했다.

## 전달물과 제한

로컬 설치기 `dist/JOBS-0.2.0-Setup-win64-a0c97697.exe`와 개발 MSIX `dist/msix/JOBS-development-1.0.2.0-x64-a0c97697.msix`를 만들었다. [설치기 메타데이터](local-installer.json)·[MSIX 메타데이터](local-msix.json)에 SHA와 소스 ID를 기록한다. 로컬 빌드와 설치 수용 검사를 수행한 CI 빌드의 바이너리가 같다고 주장하지 않는다. 새 `dist/msix/store-preparation-updates.zip`은 변경된 개인정보 처리방침과 실제 패키지 화면을 포함하는 준비 자료다.

정식 GitHub Release는 아직 게시하지 않았다. 따라서 실제 일반판의 확인 결과는 미게시 안내가 정상이며 새 버전 알림은 더 높은 버전의 정식 Release를 게시한 뒤 작동한다. 설치기는 기존과 같이 미서명 preview이며 SHA 검증은 공인 코드 서명이 아니다.

실제 Store identity가 없으므로 Store에 게시된 신규 버전의 조회·다운로드·설치 E2E, WACK, 제출·심사는 수행하지 않았다. 개발용 MSIX의 수명주기 검사와 모의 Store 결과를 실제 Store 게시 검증으로 확대하지 않는다. 계정·앱 이름 예약 후 실제 identity를 넣어 제출용 패키지를 생성하고 게시 후 최종 확인해야 한다.
