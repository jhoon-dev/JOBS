# 구조·복합 편집 준비와 화면 갱신

2026-10-28 사용자 요청. PRD BULK-01~04와 이 계약을 구현 전 `4260c32`에서 확정했다. 구현은 `202faf3`·`cf402c7`, 배정만 변하는 공수 역산의 표시 보완은 `076c210`, 계획 전용 이력의 revision 한도 검사는 `7cddc7a`이다.

명령은 owning snapshot과 데이터만 가진 해석 함수를 worker로 전달한다. worker는 live Document/위젯/저장소를 사용하지 않는다. 새 작업 ID는 GUI가 예약한 요청별 seed와 기존 입력 ID 집합을 사용해 worker에서 생성한다. 취소한 요청의 seed를 재사용하지 않는다. 결과와 선택할 새 ID는 원본 ID/revision/session/취소 확인 뒤 한 번에 반영한다.

계획 전용 명령은 기존 문서가 유효하고 불변 데이터에 쓰지 않는다는 범위에서 validatePlan과 필요 시 그래프·현재 원장 참조를 검사한다. 변경하지 않은 역사 입력의 전체 validate를 반복하지 않는다. 단순 붙여넣기의 중복 검증을 제거하고 공수 역산은 원본 계획의 순차 규칙을 보존하되 역사 자료 없는 계획 투영으로 계산한다. 전체 파일 파서/저장 검증은 유지한다. 이력은 공유하는 불변 delta로 요청을 캡처하고 성공 시 cursor만 한 단계 움직인다.

표시 입력은 별도 사본으로 worker에서 준비하고 GUI에서 이동한다. 기본 전체/원본 순서는 ID 공통 prefix/suffix와 변경 행으로 연속 삽입/삭제 및 같은 구조 갱신을 적용한다. 이전 모델 입력과 캐시는 가능한 경우 worker로 해제한다. 필터/정렬/다른 WBS나 복잡한 교체는 한 번의 안전한 전체 갱신으로 복귀한다. revision이 연속이지 않거나 계산이 새로 적용되면 준비된 표시 자료를 사용하지 않는다.

선택은 행 범위를 묶어서 적용하고 액션 활성화에서 모든 선택 셀을 열거하지 않는다. 기준선 날짜는 같은 문서 세션/기준선 ID이면 다시 변환하지 않는다. 오래된 간트는 막대를 표시하지 않으며 유효 일정 실효화와 계산 완료의 전체 갱신을 유지한다.

실패/취소와 stale 결과는 입력·dirty/revision·기준선/원장·undo/redo·원본 파일을 바꾸지 않는다. 삭제 확인 취소와 실행 취소는 별도이며 보호 작업은 어떤 부분도 삭제하지 않는다. 필터/정렬에서 캡처한 대상 ID와 원본 행 선행 번호를 해석 시점까지 고정한다. 한도 초과·불완전 TSV·사이클·마지막 행 오류를 원자적으로 거절한다.

## 구현 범위

- `DeferredTaskEdit`는 QString/캡처한 원본 행 매핑 등 데이터만 소유한 해석 함수이며 닫힌 작업 명령만 반환한다. TSV/이름 목록 해석, 신규 ID 생성, 영향 확인과 계획/그래프 검증, delta·dirty·표시 자료 준비는 worker에서 실행한다. 툴바의 작업 추가도 같은 경로다. 오류는 상태 표시줄에 표시하며 준비 중 도구 모음의 **편집 계산 취소**를 사용할 수 있다.
- `editPlan`은 작업 명령만 호출하는 내부 경계다. `validatePlan`과 현재 실적/원가의 작업 참조를 검사한다. 변경하지 않은 승인 입력/보고 메타데이터를 다시 검증하지 않는다. 고정 공수 기간의 배정률 역산은 순차 적용하고 역사 자료를 제외한 계획 사본을 사용한다. 파서·저장·복구는 기존 전체 `validate(Project)`를 유지한다.
- 이력은 `shared_ptr<const InputDelta>`를 공유한다. 이 작업 명령들의 undo/redo는 같은 worker 경로에서 준비하고 반영 시 기존 이력 cursor만 이동한다. 신규 편집 하나는 undo 한 단계이며, 100단계/추정 입력 32MiB 한도와 보호 원장은 유지한다.
- `BulkView`는 worker가 만든 독립 PlanInput, 행/위치 매핑, ID 번호, 자원 표시, 변경 범위와 루트 WBS 합계다. 기본 보기는 연속 삽입/삭제 신호 또는 `dataChanged`를 사용하고 이전 모델 입력/매핑은 worker에 해제한다. 날짜가 유효→오래됨으로 바뀌면 날짜 관련 셀도 무효화한다. 작업 자체가 같고 배정률만 바뀌는 역산도 자원 열을 갱신한다.
- 선택 열거는 선택 셀 전체 대신 행 범위를 사용하고 복원도 연속 범위를 묶는다. 같은 세션/기준선 ID의 날짜 변환을 반복하지 않는다. 필터/정렬/하위 WBS·불연속 삭제·누락한 revision·새 계산에는 기존 전체 갱신을 적용한다.

## 측정 방법과 남은 비용

초기 측정 도구를 제품 변경 전 `edbea73`에 커밋했다. 네이티브 클립보드의 지연 통지에 대응한 `19c5599` 도구 사본을 참조·최종 제품에 동일하게 적용한다. 참조는 제품 소스/CMake를 수정하지 않고 테스트 소스만 덮어쓰므로 revision에 `+dirty`가 붙으며 제품 소스 manifest도 따로 기록한다. CI는 같은 실행기의 Qt/컴파일러로 이 참조와 최종 제품을 빌드한다. `run-bulk-performance-probes.py`는 1천/1만 작업·기준선 0/3개에서 각각 100/1,000개 작업의 삽입·복제·붙여넣기·삭제와 각각의 undo를 한 번씩 실행한다. 모든 경우의 입력/저장 지점 복원도 검사한다. 타이밍을 통과 조건으로 쓰지 않는다.

`setup_ready_ms`는 액션 활성화까지의 준비 대기로 측정 구간에서 제외한다. 클립보드 통지가 지연되면 이벤트를 처리하며 최대 10초 대기하고, 계속 비활성이면 실패한 액션 이름을 기록한다. `trigger_return_ms`는 타이머 설정의 소량 계측 오버헤드를 포함한 액션 호출 구간부터 반환까지이며 삽입/삭제에는 자동화한 모달 입력/확인 지연도 포함한다. `settled_ms`는 편집 worker·Qt 완료 전달·GUI 갱신까지 포함하며 별도 worker의 이전 자료 해제 완료를 기다리지는 않는다. 심박 간격은 이벤트 전달의 관측값이며 OS 표시 완료나 FPS가 아니다. 동일 도구의 `batch_phases_ms`는 별도의 BatchTaskEdit 요청/worker 준비/Document 반영만 분리한 단일 표본이다. 화면 갱신은 포함하지 않는다. 초기 열기·명시 저장·기준선 생성은 측정에서 제외한다.

worker는 여전히 큰 Project 사본을 만들고 dirty와 InputDelta를 비교한다. 필터/정렬/불연속 변경, 유효 일정 실효화와 새 계산의 화면 비용도 남는다. 기본 보기에서도 위치/선택 순회, 자원 표시의 QString 변환, Qt 레이아웃/캐시 해제 비용은 0이 아니다. 공수 역산 K건은 순차 K회 계획 계산의 의미를 유지하므로 임의 대량 역산의 선형 시간이나 모든 입력의 일정한 응답 시간을 보장하지 않는다. 고정 벽시계/FPS/전체 메모리 상한을 주장하지 않는다.

## 최종 검증과 전후 관측

최종 제품 코드 `7cddc7a`와 측정/비교 도구 `19c5599`의 [CI 실행 40622311402](https://github.com/jhoon-dev/JOBS/actions/runs/40622311402)은 Windows/MSVC·macOS 각각 **40/40** 테스트와 네이티브 구조/모델/비동기/증분 보기 검사, XLSX 5·PDF 6·Project XML·XER TSV/MPXJ 독립 판독을 통과했다. CTest는 Windows 81.16초, macOS 66.25초였다. 로컬 MinGW 최종 제품도 40/40(133.52초), 네이티브 구조 검사와 독립 reader를 통과했다.

[원시 증거](validation/bulk-editing-2026-10-28/verification.json)에는 CI 정보, OS별 전체 성능 JSON/log와 비교본, 네이티브 PNG, 로컬 관측/CTest/독립 reader 로그를 보존한다. 1천/1만 기본·공수 일정 네 사례의 전체 결과 SHA-256은 두 OS 모두 이전 golden과 일치했다(8건). 각 OS의 4개 기본 보기 사례에서 8개 명령/undo를 실행한 결과, 구조 변경/undo의 reset 합계는 **24→0회**였고, 붙여넣기/undo는 전후 모두 reset 0회였다. 불연속/정렬 보기의 의도한 reset은 별도 UI 테스트로 검사했다.
