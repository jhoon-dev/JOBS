# 자원 등록 · 배정 · 기간별 부하 · 평준화 비교

2026-10-26 요청 구현. PRD의 J-05/J-06 첫 수직 흐름이다. 전체 자원 관리·최적화·상용 제품 호환성 완료를 뜻하지 않는다.

## 사용 순서

1. 프로젝트와 작업 기간·FS 선행·휴일을 입력한다.
2. **자원 → 자원 등록·가용량**에서 이름, 인력/장비, 기본 가용량을 등록한다. 100%는 한 명/한 대, 200%는 두 명/두 대다. `미정`은 0%와 다르다.
3. 날짜 예외는 한 줄에 `2026-10-27=0`, `2026-10-28=200`, `2026-10-29=?`처럼 입력한다. 기본값에 더하지 않고 해당 날짜의 최대 가용량을 대체한다. 중복 날짜·잘못된 값은 문서를 변경하지 않고 거절한다.
4. 작업 행을 선택하고 **선택 작업 자원 배정**에서 정수 배정률을 지정한다. 0%는 해제다. 여러 자원을 함께 배정할 수 있다. 배정된 자원은 작업 표에도 표시된다. 배정 중인 자원 삭제는 먼저 해제를 요구한다.
5. **기간별 부하·평준화 비교**를 연다. 일정 비교, A 원본 부하, A 평준화 후, B 평준화 후 탭에서 날짜·배정률·과부하·공수를 확인한다.
6. 우선순위와 탐색 범위를 변경한 뒤 **부하 계산 / 평준화 비교**를 실행한다. 조건을 변경하면 이전 결과와 저장 버튼이 무효화된다.
7. 이름을 입력하고 **A 입력·정책을 새 시나리오로 보존**한다. 문서에 불변 입력 사본을 추가하며 원본 일정/배정을 적용하거나 덮어쓰지 않는다. 미해결 시나리오도 검토 기록으로 보존할 수 있다.
8. A 입력과 저장된 B를 선택해 일정·완료일·부하를 비교한다. A/B의 계획·실적 입력이 다르면 화면에 명시하며 우선순위만의 효과로 해석하지 않는다. 파일 저장 후 재열어도 다시 비교할 수 있다.

## 데이터와 계산 의미

- `Resource`: 안정 ID, 이름, `labor`/`equipment`, 기본 최대 가용량 또는 null, 날짜별 대체 가용량.
- `Assignment`: 작업 ID + 자원 ID 쌍이 식별자이며 같은 쌍의 중복을 거절한다. 정률 배정만 지원한다.
- 모든 가용량·배정률은 정수 백분율이다. 100 = 1단위, 50 = 0.5단위. 가용량은 0~100,000 또는 null, 배정은 1~100,000이다.
- **기간 고정(duration-driven)**: 배정률 변경으로 작업 기간·실적을 자동 변경하지 않는다. 공수는 근무분 × 배정률 / 100이다. 분수 공수를 잃지 않도록 내부에서 정수 `%·분`을 사용하고 표시는 시간 단위다.
- 인력은 인시, 장비는 장비시다. 종류별로 따로 합산하며 자재·비용·생산성으로 서로 환산하지 않는다.
- 자원은 프로젝트와 같은 월~금 09–12 / 13–18 및 전체 휴일 달력을 쓴다. 날짜 가용량은 해당 날짜 근무구간에만 적용한다. 자원별 교대 달력은 후속 범위다.
- 상태일 미설정이면 현재 계획 전체 수요, 상태일 설정이면 retained remaining 예측의 **잔여 수요**만 산정한다. 완료 작업은 잔여 수요 0이다. 실제 소요 기간을 과거 자원 공수로 변환하거나 실제 배정 이력을 추정하지 않는다.
- 작업 배정 누락은 coverage와 진단으로 드러낸다. 통과는 배정된 자원의 잔여 수요에 대한 의미이며 프로젝트 전체의 인력 적정성을 보장하지 않는다.

## 기간별 부하

근무분 좌표에서 작업 시작/끝과 날짜 경계로 나누어 동시간대 배정률을 합산한다. 일평균으로 과부하를 판단하지 않는다.

각 자원·날짜에 수요 공수, 동시간대 최대 배정률, 최대 사용률(최대 배정률/가용량), 가용량을 초과한 시간, 초과 공수, 관련 작업을 표시한다. 과부하 시간은 해당 자원의 초과 구간의 길이이며 작업별로 중복 합산하지 않는다. 초과 공수는 `max(수요−가용량, 0)`의 시간 적분이다. 표는 수요가 있는 날짜만 표시하며 무수요 날짜는 생략한다. 표의 수요·초과 공수는 소수 둘째 자리로 반올림한다.

가용량이 null인 수요 구간은 INCOMPLETE다. 이때 과부하를 0으로 확정하지 않고 미정으로 표시한다. 알려진 가용량의 초과는 CONFLICT, 알려진 구간 전부 충족은 VALID다. 알려진 초과와 미정이 섞이면 상태는 INCOMPLETE이고 알려진 초과도 진단한다. 가용량 0%에 양의 수요가 있으면 명확한 과부하다.

## 평준화 정책 `serial-no-split-v1`

원본 논리 일정 또는 상태일 이후 잔여 예측을 기준으로 전체 작업을 대상으로 하는 직렬 생성 휴리스틱이다.

1. FS 선행 작업이 모두 배치된 작업 중 선택한 우선순위(행 순서 / 짧은 잔여 기간 / 긴 잔여 기간)를 적용한다. 동률은 프로젝트 행 순서다. 입력이 같으면 결과도 같다.
2. 원본 잔여 시작보다 앞당기지 않고 새 선행 완료 이후에서 탐색한다.
3. 배정된 모든 자원의 **구간 전체** 가용량을 충족하는 첫 시작을 찾는다. 예약 수요/가용량이 바뀌는 경계를 건너뛰며 탐색한다. 미정 가용량 구간은 가용하다고 간주하지 않고 이후 알려진 구간을 찾을 수 있다.
4. 작업/잔여 구간을 분할하지 않고 기간·배정률·공수를 유지한다. 여유를 넘어 지연할 수 있다. 자원 대기 원인에는 자원 이름/ID·첫 충돌 시각·수요/가용률을 기록하고, 선행 지연도 ID로 표시한다.
5. 실제 시작·완료는 고정한다. 시작한 작업은 실제 시작을 유지하고 잔여 시작/예측 완료만 늦춘다. 완료 작업은 이동하지 않는다. 과거 실제 선후행 모순은 원래 예측 진단에 남는다.
6. 탐색 범위는 **계획 시작부터 1~5,200 근무일**, 기본 260일이다. 달력 엔진의 20년 범위도 적용한다. 배치하지 못하면 작업/원인과 INCOMPLETE(탐색 중 미정 용량 존재) 또는 CONFLICT를 반환하고 부분 일정을 확정하지 않는다. 이는 최적 해 부재의 증명이 아니다. 우선순위·가용량·범위를 바꿔 다른 시나리오를 비교한다.

평준화 결과의 CPM 총/자유 여유·임계를 재계산하지 않는다. 비교 화면은 이를 표시하지 않는다. F9와 기본 간트는 계속 현재 계획/잔여 예측을 보여준다. 평준화 결과의 원본 적용·간트 겹침·작업 분할·개별 작업 우선순위·수동 자원 곡선·공수 고정(work-driven)·멀티프로젝트 평준화는 후속 범위다.

## 저장·이력과 이전 파일

schema 5는 계획과 기준선 입력에 resources/assignments를 포함한다. 기준선 대비 자원 정의/가용량·작업별 배정 변경도 비교한다.

`scenarios`는 이름, ID, UTC 저장시각, 원본 문서 ID/revision, 계획 입력·달력·자원·배정, 상태일·실적 원장, 우선순위·범위·정책 버전을 보존한다. 현재 입력을 바꿔도 이전 시나리오를 수정하지 않는다. 파생 결과는 저장된 입력과 고정 정책으로 비교 창에서 재계산하며, 파일에 계산 결과를 별도 동결하지 않는다. 향후 의미 변경은 새 정책 버전으로 분리해야 하며 미지원 정책은 무음 대체하지 않고 거절한다. 사본 저장은 기존 시나리오의 출처를 유지한다.

화면 계산은 불변 스냅샷을 QtConcurrent로 처리하고 세대 번호·문서 ID/revision으로 오래된 결과를 거절한다. 보존 시에도 원본 revision 일치를 확인한다. 읽기 전용은 비교만 허용한다. schema 1~4는 빈 자원/배정/시나리오를 기본으로 읽고, 다른 이름으로 schema 5 사본을 만들어 원본 bytes를 보존한다. 이전 schema 4 기준선도 입력·결과 재검산을 유지한다.

`jobs_resource_tests`는 위 사례, 날짜 예외·휴일·다중 배정, 독립 분 단위 수요 oracle, FS·기간·공수 보존·결정성, 실패 편집의 원자성, 읽기 전용, 불변 기준선/시나리오, 사본 출처, 파일 왕복, 잘못된 참조·정책 거절, schema 4 사본 이관을 검사한다.

`jobs_resource_ui_tests`는 실제 대화상자로 자원 등록/오류/새 ID, 작업 배정/표 반영, 최대 부하/과부하, 옵션 변경 시 이전 결과 무효화, 성공/미해결 시나리오 보존·A/B 비교, 원본 불변·저장/재열기를 검사한다.

후속 원가 증분(schema 6)은 자원 유효일 단가와 배정 공수로 계획 금액을 산정한다. 공수 단위 자체는 혼합하지 않으며 동일 통화의 금액으로 집계한다. 상세는 [원가·EVM 계약](costs-evm.md)을 따른다.
