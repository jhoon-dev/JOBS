# 통합 검증·대용량 성능·계산 취소

2026-10-26 · PRD PERF-01~04 / SUP-02·05 / DESK-06. 사용자 요청에 따라 구현 전에 요구사항과 완료조건을 추가했다. PRD 추가 커밋 `6f77b03` 이후 구현했다. 아래 구현 범위와 측정 증거를 완료 판단의 근거로 사용한다.

## 측정 계약

동일한 생성 규칙과 고정 입력으로 1천/1만 작업을 측정한다. 기본 일정과 공수/달력/분할 일정은 별도 사례다. 과도한 선행 체인이 계산 달력의 20년 범위를 넘지 않도록 고정 폭의 단계 그래프를 사용한다. 표본 수, 성공/실패/취소, 전체 작업/선행/자원/달력/중단 수, 계산 정책, 완료일, UI 준비·스크롤 시간, 프로세스 최대 메모리를 기록한다.

반복 표본의 median과 nearest-rank 관측 P95를 기록하며 소수 표본의 관측값을 모집단 성능 보장으로 해석하지 않는다. 메모리는 OS별 프로세스 최대 resident/working-set 값이며 해당 시나리오의 순수 증분과 다르다. 사례별 별도 프로세스로 실행하고 OS·CPU·Qt·컴파일러·빌드/소스 revision을 보존한다. 10만 작업, 다중 사용자, 실제 고객 데이터와 경쟁 제품 비교는 후속 검증이다.

## 취소 계약

주 일정의 입력 검증·네트워크·달력/공수·전진/후진 배치에 협력 취소 검사 지점을 둔다. Qt와 독립된 요청별 제어 객체가 취소 플래그와 진행 수치를 공유하며 계산은 불변 Project 사본을 사용한다. 취소 결과에는 날짜/완료일을 포함하지 않고 별도 상태·진단을 반환한다. 정상 결과로 캐시하거나 기준선으로 승인하지 않는다. 새 요청은 새 제어 객체를 사용한다. 자동 재계산 대기열은 사용자 취소 시 비우며 문서 전환/종료 시 이전 요청을 종료한다. 일반 파일 저장/승인 기록은 취소 대상이 아니다.

## 성능 개선의 불변조건

캐시는 한 계산/한 스냅샷 범위의 불변 달력과 가용시간에 한정한다. 입력 변경 뒤 재사용하지 않고 공수 목표·actual·baseline을 덮어쓰지 않는다. 날짜·여유·driving 관계·공수·부하·원가의 기존 회귀 결과를 보존해야 한다. 표는 전체 행을 유지하고 간트는 화면 주변 행을 그리되 계산 그래프와 선택 ID는 전체를 유지한다. 줌/스크롤/선택/필터/기준선 변경과 작업 드래그를 검사한다.

## 통합 검증

독립 기대값이 있는 혼합 달력·공수·중단·자원 비용 프로젝트로 전체 운영 흐름과 저장·복구를 검사한다. 일반 회귀·UI 취소/재시작·작은/대형 간트·대용량 측정을 Windows/macOS CI에 연결한다. 예외·시간 한도·취소·불완전 결과를 유효 일정으로 취급하지 않는다. 승인·실적 원장을 보존하고 요청 revision/session이 다른 결과는 폐기한다.

## 구현과 사용

F9의 주 일정 계산 중 프로젝트 메뉴/도구 모음의 **일정 계산 취소**를 누른다. 입력 검증·선행관계·달력/공수·전진 배치·후진 여유 단계를 100ms 간격으로 표시한다. 취소 후 진단은 `CALCULATION_CANCELLED`, 표는 미계산, 간트는 날짜 막대 없이 표시한다. 계산 도중 입력을 바꾼 경우 revision 검사가 우선하여 오래됨으로 표시할 수 있다. F9는 새로운 요청으로 다시 계산한다. 명시 취소는 자동 재계산 대기도 비운다. 대시보드/기준선 승인/평준화 대화상자 전체의 취소는 이번 범위가 아니다.

Qt와 독립된 `CalculationControl`이 협력 취소를 전달한다. 취소 예외는 날짜 범위/충돌 처리와 구분해 최상위 계산 경계에서만 취소 결과로 바꾼다. 문서 ID/revision/정책/상태일과 UI session을 확인하며 종료/문서 교체 요청도 취소한다. 승인 기준선과 실제 원장은 입력 사본에서 읽으며 바꾸지 않는다.

달력은 시작일·실제 근무 요일/시간대·휴일·수동 중단의 전체 의미로 키를 만들고 불변 구간을 공유한다. 공수 격자는 작업/자원 달력·배정 자원 ID/배정률을 포함한다. 한 계산 또는 한 간트 입력 사본에서 최대 1,024개 캐시 항목을 유지한다. 간트 캐시는 입력 교체 때 비우며 스크롤 동안 같은 불변 입력만 재사용한다. 가용 자원 배정은 인덱스로 찾고 공수 일정의 준비 작업은 선행 차수/안정 순서 집합에서 고른다. 기존 자원 우선순위 동률은 작업 순서를 유지한다.

표는 전체 작업 행을 유지하고 갱신 중 재그리기를 억제한다. 200행 초과 간트는 보이는 행 앞뒤 4행과 해당 후행 작업의 연결선을 만든다. 장면의 전체 크기/날짜/작업 ID는 보존한다. 화면 밖 ID를 선택하면 해당 행을 보여 주며 기준선·배율·창 크기 변경도 같은 범위를 갱신한다. 연결선 수는 실제 선행관계 수에 의존하며 모든 종류 그래프에 고정 객체 수를 보장하지 않는다.

## 재현

```powershell
.\scripts\dev.ps1 -TestOnly
# Qt/컴파일러가 PATH에 있는 셸에서 실행
python scripts/run-performance-probes.py --build-dir build --repeats 3
```

일반 CMake Release 빌드도 동일한 `jobs_performance_probe`를 만든다. 스크립트는 실행 파일의 build/Release 위치도 찾고 각 사례를 별도 프로세스로 실행한다. 사례당 180초 한도이며 실패/시간 초과는 JSON과 종료 코드에 명시한다. `build/performance`의 JSON에는 원시 표본과 로그가 남는다. CI는 Windows/MSVC와 macOS에서 CTest·독립 XLSX/PDF 검사 뒤 같은 네 사례를 실행하고 `performance-Windows`, `performance-macOS` artifact로 보존한다. CI의 OS별 절대 시간은 로컬과 직접 비교하지 않는다.

`jobs-perf-layered-v1`은 100개 폭의 FS0 단계 그래프이며 모든 작업에 60분을 입력한다. 공수 사례는 자원 8개, 별도 오후 달력 1개, 고정 공수/고정 단위/고정 기간과 25작업마다 같은 중단을 사용한다. 기간 고정 작업의 자원 부하는 일정 날짜와 구별한다. 측정은 주 일정과 표/간트 준비·12위치 스크롤을 대상으로 하며 대규모 기준선/실적/EVM/평준화/출력 비용을 대표하지 않는다.

## 정합성·운영 흐름 증거

최적화 전 `9a401853bb2c42b90ceba354b6671b298a2d8e0f`의 domain/calculation 원본을 별도로 빌드해 같은 1천 작업 두 사례의 전체 TaskSchedule 필드를 직렬화했다. 그 SHA-256을 [참조 기록](validation/performance-2026-10-26/reference-schedule-sha256.json)과 `PerformanceProbe.cpp`에 고정했다. CI도 전 작업의 시작/완료·조기/늦은 날짜·총/자유 여유·임계·driving 선행·실제/잔여 플래그가 같은지 검사한다. 1만 사례는 전체 결과의 반복 결정성을 검사하며 최적화 전 1만 실행을 검증했다고 표시하지 않는다.

추가 CTest는 다음과 같다.

- `calculation_cancellation`: 사전 취소, 실제 worker의 달력 준비/후진 단계 취소, 부분 결과 없음, 2만 작업 재시작, 입력 불변, 서로 다른 달력 의미의 캐시 격리.
- `performance_cancellation_ui`: 1천 작업 전체 표·화면 주변 간트, 끝 행/화면 밖 ID 선택, 기준선/관계/배율/창 크기, 취소 직후 완료 경합, 재시작, 명시 취소의 대기 재계산 제거, 문서 교체 후 늦은 응답 폐기.
- `integrated_project_workflow`: 생성/WBS/달력·공수·중단·자원 단가 → 계획/승인 → 실적/원가 → 예측/비교/EVM/평준화/시나리오/보고 → 취소/저장/독립 재열기/미저장 체크포인트 복구. 별도 기대값 BAC 25,000 / PV 9,500 / EV 9,500 / AC 10,000 최소 통화단위와 분할 작업 11:00 완료를 대조한다. 다른 작업의 고정비 0도 명시하여 미정을 0으로 채우지 않는다.

기존 회귀는 공수·부하·단가·원가·실적 보존과 드래그/필터/복구/출력 경계를 계속 검증한다. XLSX/PDF는 기존 독립 reader 검사를 유지한다. 저장 형식 schema 9와 이전 계산 엔진/기준선 형식을 유지한다.
