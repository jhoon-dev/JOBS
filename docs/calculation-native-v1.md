# 초기 native 일정 계산 정책

PRD-01/03, CAL-01/03/04 일부, F01/F04/F12 일부의 실행 가능한 첫 계약이다.
다른 semantic profile, 상용 제품 동등성, 전체 PRD의 수용 완료를 뜻하지 않는다.

## 입력과 시간 의미

정책 ID `native-fs0-workminutes-v1`, 엔진 `jobs-cpm-0.1`.
모든 실행 작업에 같은 프로젝트 달력을 적용한다. 월–금 09:00–12:00 / 13:00–18:00,
1일 480 근무분이며 사용자가 지정한 날짜는 하루 전체 휴일이다.
표시 시각은 시간대 없는 현지 civil time이다. UTC/DST 변환, 야간 근무, elapsed duration,
작업별/자원별 달력은 지원하지 않는다. 기획 F03의 연속 09–17시 profile과 구분한다.

프로젝트 시작 날짜의 첫 근무 09시를 기준으로 ASAP 계산한다. 시작 날짜가 휴무면 다음 근무일을 쓴다.
기간 입력은 시간 수(`8`, `1.5`) 또는 분(`1m`)이며 저장은 정수 근무분이다.
시간 소수 입력은 최대 세 자리이며 정수 분으로 정확히 환산되어야 한다. 무음 반올림하지 않는다.
빈 기간은 미정(null), 0은 마일스톤이다. 각 기간 한도는 5,000,000분이다.
계산 horizon은 시작일부터 20×366일, civil year 9999 이내다. 넘으면 명시 진단하고 일정은 반환하지 않는다.

관계는 FS, 0 lag만 지원한다. 표에 쉼표로 선행 행 번호를 입력하지만 저장은 stable task ID로 한다.
선행이 없으면 프로젝트 시작에서 ASAP으로 시작한다. 행 번호는 저장 identity가 아니다.
자기참조·누락 참조·순환은 계산 충돌이다. 순환 진단에는 downstream 작업을 제외한 실제 닫힌 ID 경로를 준다.
선행 완료가 금요일 18시면 양의 기간 후행은 다음 근무일 09시에 시작하고,
0기간 마일스톤은 금요일 18시 경계에 머문다. 점심 전 완료 12시와 다음 양의 작업 시작 13시를 구분한다.

## 결과와 신선도

동일 달력의 근무분 좌표에서 DAG 전진·후진 계산을 한다.
자연 프로젝트 완료는 최대 조기 완료이며 이를 후진 계산 anchor로 삼는다.
총여유 = 늦은 시작−조기 시작, 자유여유 = 후행 최소 조기 시작−조기 완료다.
후행 없는 작업의 자유여유 anchor는 자연 프로젝트 완료다. 총여유 0을 임계 작업으로 표시한다.
여러 임계경로와 조기 시작을 결정한 선행 ID 목록을 보존한다.
required finish, 음수 여유, 별도 deadline, 수동 제약은 아직 없다.

결과는 documentId·inputRevision·engineVersion·profile·진단을 포함한다.
입력이 부족하면 INCOMPLETE, 순환·참조·날짜·horizon 오류면 CONFLICT이며
전체 완료일과 작업 날짜를 반환하지 않는다. 유효한 결과도 자원 가용성은 미검증이다.
빈 계획에도 완료일을 붙이지 않는다.

QtConcurrent worker에 불변 Project 복사본을 전달한다. UI를 막지 않고 계산하는 동안 편집할 수 있다.
Application은 수신 시 현재 documentId/revision/profile과 대조한다. 다르면 STALE로 보존하고
UI는 날짜를 숨긴다. 계산 후 편집해도 즉시 STALE이다. 계산이 입력 사실이나 저장 상태를 수정하지 않는다.
계산 cache는 파일에 저장하지 않으며 재열기 후 재계산한다. 작업 취소·진행률·성능 보장은 후속 범위다.

## 재현 예제

2026-10-26 시작 프로젝트에 아래 작업명을 순서대로 만들고 기간과 선행 열을 편집한 뒤 F9를 누른다.

| 행 | 작업 | 기간(h) | 선행 행 | 기대 ES/EF(근무시간) | 총여유(h) |
|---|---|---|---|---|---|
| 1 | A | 16 | 빈칸 | 0 / 16 | 0 |
| 2 | B | 24 | 1 | 16 / 40 | 0 |
| 3 | C | 8 | 1 | 16 / 24 | 16 |
| 4 | D | 16 | 2,3 | 40 / 56 | 0 |

자연 완료는 56 근무시간, 2026-11-03 18:00이다. 11월 2일을 휴일로 추가하면
완료는 11월 4일 18:00이 된다. 작업 기간을 지우면 전체 완료일 대신 입력 불완전 진단이 나온다.
A의 선행에 D(4)를 입력하면 순환 진단을 보며, 관계를 지우고 F9로 다시 계산할 수 있다.

## 검증

`jobs_schedule_tests`는 Qt·파일 없이 F01의 56h/16h 여유, 여러 임계경로, 결정 선행,
주말·휴일·점심·마일스톤 경계, 시작 휴무일, 미정 기간, 닫힌 순환 경로,
누락·자기참조, horizon·잘못된 날짜, 0기간·빈 계획, 같은 입력의 결정성을 확인한다.
파일 테스트는 새 입력 저장·재열기와 이전 schema 사본 이관을, 화면 테스트는
입력→계산→편집→STALE→재계산과 충돌/미정 시 날짜 숨김을 검사한다.

아직 WBS 이동, 기준선, 실적, 자원, 네 관계/lag, timezone/DST, 강제종료 복구,
교환 호환성 및 1천/1만/10만 작업 성능은 검증 범위에 포함하지 않는다.
