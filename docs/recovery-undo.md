# 자동 저장·비정상 종료 복구·실행 취소

2026-10-26 사용자 요청으로 FILE-06, DESK-03/04/06과 편집 이력의 첫 흐름을 구현했다. 자동 저장은 **별도의 복구 체크포인트**이며 원본 `.jobs`에 대한 명시 저장, 승인 기준선, 백업, 실행 취소를 대체하지 않는다. 프로젝트 형식은 schema 6을 유지한다.

후속 작업 달력/PDM 증분부터 프로젝트 schema 7을 기록한다. 복구 envelope schema 1은 내부 projectSchema 6/7을 읽으며 [확장 입력 계약](pdm-calendars.md)을 따른다. 아래 schema 6 표기는 최초 구현 시점이다.

## 자동 저장 사용

- **자동 저장·복구 → 자동복구 저장 사용**은 기본 켜짐이다. 편집이 멈춘 뒤 2초, 변경이 계속되면 기본 30초 간격으로 저장을 요청한다. 간격은 5~300초로 설정하며 사용 여부와 함께 이 PC의 사용자 설정에 보존한다.
- **복구본 지금 저장**으로 요청할 수도 있다. 변경이 없거나 읽기 전용인 문서는 자동 저장하지 않는다. F9 계산·뷰 필터·내보내기는 입력 변경이 아니므로 체크포인트를 늘리지 않는다.
- 상태 표시줄에서 대기/저장 중/완료 revision·세대/실패를 구분한다. 원본의 미저장 별표는 자동 저장으로 없어지지 않는다. 저장 도중 추가 입력이 생기면 완료 revision과 현재 revision을 구분한다.
- 입력을 복사한 뒤 직렬 백그라운드 작업으로 기록한다. 간격은 요청 시점이며 파일 쓰기 완료 시간을 보장하지 않는다. 진행 중인 저장이 끝난 뒤 후속 변경을 처리한다. 실패를 명시하고 다음 간격에 다시 시도하며 이전 정상 세대를 보존한다.
- 끄면 새 자동 저장 요청을 중지한다. 이미 진행 중인 기록은 완성할 수 있고 기존 복구본은 유지한다. 원본 저장/명시적 닫기·버리기는 별도 수명 규칙을 따른다.

기본 위치는 Qt의 사용자별 `AppLocalDataLocation/recovery`다. 일반적인 Windows 위치는 `%LOCALAPPDATA%/ToolMoa/JOBS/recovery`, macOS는 `~/Library/Application Support/ToolMoa/JOBS/recovery`다. 정확한 경로는 복구 선택 창과 상태 툴팁에 표시한다. `.jobs` 파일만 다른 PC로 전달해도 열리며 복구 폴더·잠금·계산 캐시·실행 취소 이력을 함께 옮길 필요가 없다.

## 비정상 종료 뒤 복구

2026-10-30 진단 보완: 손상/미지원 세대와 세션 검색 실패는 안정 오류 코드·원인·해당 파일/세션 경로를 가진 Diagnostic을 보존한다. 복구 선택 창은 공통 포맷터로 한국어 설명·수정 안내를 표시하며 손상 JSON/버전/무결성 오류에는 다른 검증된 세대 또는 명시 저장본을 열도록 안내한다. 검증 실패 세대는 복구 버튼을 활성화하지 않고 검색/표시만으로 원본이나 복구 bytes를 수정하지 않는다. 기존 error 문자열 소비자는 포맷된 설명을 받는다.

1. 다시 실행하면 복구 가능한 이전 세대를 검색한다. 실행 중인 다른 앱의 복구 세션은 제외한다. 복구본이 있으면 선택 창을 표시하며 현재 모달 작업이 열려 있으면 메뉴에 발견한 세대 수를 알려준다. **자동 저장·복구 → 복구본 선택**으로 다시 검색할 수 있다.
2. 프로젝트·문서 ID, 캡처 UTC, 체크포인트 revision, 마지막 명시 저장 revision, 세대, 원본 경로/상태를 확인한다. 원본 일치/변경/없음·이동/확인 불가를 구분한다. 원본이 기록된 저장 지점과 일치할 때만 작업 추가/제거/변경 수와 WBS·자원·배정·달력·원가·상태일/원장 변경 요약을 보여준다. 원본이 달라졌거나 없으면 비교 불가를 명시한다. 손상·미지원·확인할 수 없는 잠금은 진단으로 남기며 정상 데이터로 오표시하지 않는다.
3. 검증된 세대를 선택해 **복구 사본 열기**를 누른다. 선택 후 잠금을 얻고 파일의 해시와 내용을 다시 검증한다. 원본을 자동으로 열거나 덮어쓰거나 외부 변경과 병합하지 않는다. 현재 다른 미저장 문서가 있으면 기존 저장/버리기/취소 흐름을 따른다.
4. 복구 문서는 새 document ID와 `derivedFrom` 계보를 가진 편집 가능한 메모리 사본이다. 작업 ID·배정·단가·기준선·실적·원가·시나리오와 기존 사실의 출처는 유지한다. 원본 경로에 다시 연결하지 않고 새 파일 저장을 요구한다. 파일이 이동/삭제되었거나 다른 앱이 원본을 쓰는 중이어도 사본을 복구할 수 있다.
5. 새 `.jobs` 저장이 성공할 때까지 선택한 원래 복구 세션을 보존한다. 복구 사본을 저장하면 그 세션을 정리한다. 사본을 저장하지 않고 닫거나 다른 문서로 이동하면 원래 선택한 복구본은 다시 선택할 수 있게 남긴다. 사본 편집도 새 자동 저장 대상이다.

**나중에**는 복구본을 그대로 둔다. **선택 세션의 복구본 모두 버리기**는 별도 확인 후 해당 세션의 완료 세대 파일만 삭제하며 원본 `.jobs`를 건드리지 않는다. 실제 선택/삭제는 세션 잠금 획득 후 수행한다. 소유자를 확인할 수 없는 잠금을 시간 경과만으로 탈취하지 않는다.

복구할 수 있는 범위는 **마지막 완료 체크포인트까지**다. 그 이후 입력이나 아직 확정하지 않은 셀/대화상자 텍스트는 포함되지 않을 수 있다. 캡처 시각·명시 저장/복구 revision과 원장 건수를 표시하며 미복구 변경 수를 추측하지 않는다. 자동 저장 쓰기 중 전원 손실에 대한 물리 디스크 내구성, 장치 고장, 복구 폴더 삭제, 네트워크 파일시스템 원자성까지 보장하지 않는다.

## 파일과 동시 작업 계약

`JOBS-RECOVERY` schema 1은 프로젝트 schema 6 입력 전체, 원본 경로/저장 fingerprint, 마지막 명시 저장 revision, 원본 읽기 전용/이관 상태, 캡처 UTC, 세션 UUID·세대, 완료 marker와 SHA-256을 담는다. 캐시와 실행 취소 스택은 포함하지 않는다. 구버전 `.jobs`를 읽어 편집한 경우에도 변환된 메모리 입력을 기록하며 구버전 원본 bytes는 유지한다.

세션은 UUID 하위 폴더와 `session.lock`을 갖는다. 프로세스가 살아 있으면 다른 실행이 읽기/삭제 소유권을 가져가지 않는다. 프로세스 종료가 확인된 stale lock은 Qt의 잠금 절차로 처리한다. 쓰기는 새 세대의 `QSaveFile` 임시 파일 → 전체 입력/무결성 검증 → flush → 원자적 commit 순서다. 직접 덮어쓰기 fallback을 사용하지 않는다. 임시 파일은 완료 세대로 검색하지 않는다.

최근 **정상 3세대**를 유지한다. 손상된 세대는 자동으로 정리하지 않으며 이전 정상 세대를 명시적으로 선택할 수 있다. 원본 저장·입력이 저장본과 같아짐·문서 교체·명시적 닫기/버리기 때 작업 세션을 종료한다. 종료된 작업의 늦은 commit을 취소하고 기록/정리를 직렬화해 오래된 복구본이 되살아나지 않게 한다. 정리 실패는 별도로 표시하며 무음 성공 처리하지 않는다.

파일당 64 MiB, 세션 검색 1,000개, 세션 안 검색 항목 1,000개 한도다. 알 수 없는 버전/필드, 잘못된 참조·수치·날짜, 해시 불일치, 미완료 marker를 거절한다. UUID 경로와 알려진 세대 파일만 취급하고 링크/정션·경로 탈출을 거절한다. 하위 디렉터리를 재귀 삭제하지 않는다. 완료되지 않은 임시/알 수 없는 파일은 자동 정리 범위 밖이다. 비협조 프로세스가 검사 직후 경로를 바꾸는 경쟁은 완전 차단하지 못한다.

## 실행 취소·다시 실행

**편집 → 실행 취소/다시 실행** 또는 OS 표준 단축키를 사용한다. Windows는 Ctrl+Z / Ctrl+Y, macOS는 Cmd+Z / Cmd+Shift+Z가 기본이다. 셀 편집기 안에서는 먼저 확정 전 텍스트의 취소가 동작하며 셀 확정 뒤 문서 단위 취소가 동작한다.
저장·계산·보고서·메뉴 명령과 정상 닫기에서는 활성 셀을 먼저 확정한다. 닫기 취소는 그 입력과 복구 세션을 유지한다. 비정상 종료 시 확정하지 않은 편집기/대화상자 초안은 체크포인트 범위 밖이다.

작업 추가/이름/기간/선행, WBS 생성/이름/이동/소속/빈 삭제, 휴일·상태일, 자원 등록/가용량/단가/삭제/배정, 통화·작업 비용 편집을 한 번의 성공한 문서 변경 단위로 되돌린다. 고유 ID와 입력 간 참조를 함께 복원한다. 실패한 입력이나 값이 같은 입력은 이력을 추가하거나 다시 실행을 지우지 않는다. 취소 후 다른 편집을 하면 다시 실행 분기를 제거한다.

승인 기준선, 제출된 일정 실적/실제원가·물리 진척, 저장 시나리오는 불변 사실이다. 이들을 성공적으로 추가하면 이전 편집 스택의 경계를 만들며, 실행 취소로 사실을 삭제하지 않는다. 실적·원가는 사유가 있는 정정 보고를 사용한다. 편집 메뉴/주 화면에 경계 이유를 표시한다. 경계 이후 일반 입력은 다시 취소할 수 있다.

이력은 최대 최근 100단계 및 추정 입력 저장량 32 MiB다. 2026-10-27 증분부터 전체 계획 두 벌 대신 변경한 값/요소의 전후를 저장한다. 벡터 길이가 달라지면 공통 앞뒤를 제외한 구간을 보존하고 일반 이름 변경은 이름만 저장한다. 오래된 단계부터 제거하며 한 단계가 한도를 넘으면 해당 변경은 적용하되 취소 이력을 비우고 한도 안내를 표시한다. 추정량은 문자열/입력 구조 기준이며 allocator 전체 메모리의 절대 보장은 아니다. 대형 단일 변경과 복잡한 재배치는 여전히 한도에 도달할 수 있다. 수용 조건과 측정은 [편집 성능 계약](editing-performance.md)을 따른다.

취소/다시 실행도 **새 revision**을 부여한다. 숫자를 과거로 되돌리지 않으며 기존 계산·예측·비교·보고를 오래된 결과로 처리한다. 저장 입력으로 돌아오면 미저장 표시를 해제하지만 현재 메모리 revision이 디스크 revision과 같다는 뜻은 아니다. 보고서에서는 이를 구분한다. 명시 저장은 취소 이력을 유지하고, 최초 파일 저장도 유지한다. 새로 만들기/열기/복구/기존 경로에서 독립 사본 저장은 이력을 새로 시작한다. 복구 전 실행 취소 스택은 재구성하지 않는다.

## 검증 범위

- `undo_contract`: 여러 입력의 정확한 역순/재실행과 ID 보존, 단조 증가 revision·STALE, 저장 지점/분기/no-op/거절·읽기 전용·불변 사실·100단계/메모리 한도·observer 수명.
- `recovery_crash_file`: 별도 프로세스를 실제 kill한 뒤 잠금/정상 3세대 복구, flush 후 commit 직전 kill, 처음 저장 전 문서, Unicode 경로·원장 보존, 손상/미완료/미지원·선택 후 변경, 원본 이동/변경, 쓰기 실패·독점 삭제·경로 탈출·확인 불가 잠금·구버전 원본 보존.
- `recovery_ui`: 백그라운드 저장과 명시 저장/새 입력의 경쟁, 연속 편집 간격·일시 중지·읽기 전용·실패 표시, 시작 복구 선택/사본 저장, 문자/문서 취소 단축키, 복구 후 새 revision의 보고 출처, 닫기 취소/버리기, 나중에/명시 삭제.

기존 14개를 포함한 CTest 17개가 로컬 Windows에서 통과했다. Windows 네이티브 복구 창과 주 화면의 한글·revision·상태·편집 이력 안내, 활성 셀 확정 후 계산과 닫기 취소를 별도 확인했다. 기존 XLSX/PDF 5개 출력물도 독립 reader로 다시 검증했다. 강제 전원 차단·실제 디스크 고장/장치 제거·클라우드 동기화/다중 writer·대용량 반응성·이력의 디스크 영속화는 별도 검증/후속 후보로 유지한다.

후속 제약/간트 증분부터 프로젝트 schema 8을 기록하고 복구 내부 projectSchema 6/7/8을 읽는다. 제약·마감일 변경과 한 번의 드래그 commit도 일반 편집 이력/체크포인트 범위다. 미리보기는 입력이 아니며 저장/복구하지 않는다. [제약·간트 계약](constraints-gantt.md)을 따른다.
