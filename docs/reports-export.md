# 프로젝트 대시보드·보고서·엑셀/PDF 출력

2026-10-26 사용자 후속 요청으로 구현한 J-14의 첫 보고 흐름이다. 원본 계획/잔여 예측과 원가 분석을 정적 보고서로 출력한다. 설정은 현재 대화상자와 출력물에 보존하며 `.jobs` 형식은 schema 6을 유지한다.

## 사용 순서

1. 프로젝트의 기간·선행관계, 자원·배정, 단가·고정비를 입력한다. 기준선을 승인 저장하고 상태일·일정 실적·누적 실제원가·물리 진척을 보고하면 비교 지표를 사용할 수 있다.
2. **보고서 → 프로젝트 대시보드·보고서**를 연다. 주 화면의 WBS/기준선을 이어받으며 프로젝트 전체도 선택할 수 있다. 초기 기준선 선택이 없으면 최신 승인본을 선택한다. `기준선 없음`으로 현재 계획/실제만 조회할 수도 있다.
3. WBS, 기준선, EAC 가정을 선택한다. 변경할 때마다 새 스냅샷을 계산한다. 일별 명세 기간은 종료일을 포함한다. 잘못된 기간은 오류를 표시하고 출력을 막는다.
4. 대시보드와 명세를 확인한 후 전체/일정/자원/원가 출력 범위를 선택한다. **엑셀 내보내기** 또는 **PDF 내보내기**에서 새 파일명을 지정한다. PDF는 A4/A3, 가로/세로, 본문 9~12pt를 선택한다.

기존 파일을 덮어쓰지 않는다. 같은 이름이 있으면 새 이름을 사용한다. 취소·읽기 전용 조회·출력은 입력/revision/실적/기준선/저장 상태를 바꾸지 않는다. 계산 중이나 파일명 선택 중 원본이 바뀌면 오래된 결과를 버리고 재계산을 요구한다. 출력 중 변경되면 생성 파일의 원본 revision을 보존하고 다음 출력을 막는다.

## 내용과 집계 범위

| 화면/명세 | 내용 |
|---|---|
| 대시보드 | 작업 수·실제 완료 보고·완료 예측·계획 임계·기준선 대비 지연·공유 과부하·현재 예산/실제·BAC/EV/CPI/EAC와 근거 |
| 일정 | 작업 ID/WBS·기간·계획 날짜·총여유/임계, 실제 날짜·잔여·예측 완료·기준선 날짜/편차, 선택 범위 밖 FS0 선행 참조 |
| 자원 | 등록/날짜별 가용량, 작업 배정, 기간별 선택/전체 공수·최대 배정, 과부하/미정 예외 |
| 원가 | 작업별 현재 예산/BAC/PV/EV/AC, CV/SV/CPI/SPI/EAC/ETC, 현재/기준선 WBS 집계, 일별/누적 명세 |
| 진단·출처 | 불완전/충돌/미정, 문서 ID/revision, 보고서 ID/생성 UTC, 미저장 여부, 상태일·필터·기준선·정책·달력·통화·가정 |

전체 출력은 14개 표를 포함한다. 분야별 출력은 해당 명세와 공통 대시보드·진단·출처를 포함한다. 전체/원가 PDF에는 화면과 같은 PV/EV/AC 누적 추이도 포함한다. 미정은 선으로 연결하거나 0으로 채우지 않는다.

- 전체 실행 그래프를 계산한 뒤 현재 WBS의 고유 작업을 선택한다. 외부 선행관계를 자르지 않는다. 임계는 계획 CPM의 판정이며 잔여 예측/평준화의 임계를 뜻하지 않는다. 일정이 불완전/충돌이면 날짜를 숨기고 진단을 출력한다.
- 자원 `선택 공수`는 선택 작업의 배정, `전체 공수/최대배정/과부하`는 그 자원을 공유하는 전체 프로젝트 수요다. 상태일이 있으면 잔여 수요만 산정한다. 미배정 작업은 수요 검증에 포함되지 않으며 배정 작업 수를 함께 표시한다. 전체 등록 명세에는 미배정 자원도 포함한다.
- 기간 필터는 일별 자원/원가 명세·추이와 과부하 지표에 적용한다. 작업 수·계획/BAC·상태일 누적 실제/EV·완료일을 기간 필터로 재정의하지 않는다. 과부하는 자원별 겹친 시간의 합이며 프로젝트 경과시간과 다르다.
- 현재 예산/실제는 현재 선택 작업, EVM은 승인 기준선 코호트다. 전체 선택은 삭제된 기준선 작업도 포함한다. WBS 선택은 현재 해당 WBS 작업 ID와 기준선의 교집합이다. 빈 WBS는 전체로 확대되지 않는다. 상위/하위 WBS 행을 다시 더하지 않는다.
- 일별 현재 실제와 기준선 코호트 AC는 별도 열이다. 기준선이 없어도 현재 실제를 조회한다. 상태일 이후 EV/AC를 예측하지 않으며 실제원가를 단가 변경으로 재평가하지 않는다. [원가 계산 계약](costs-evm.md)을 따른다.
- 가용량 미정과 0%, 금액 미정과 확인된 0을 구분한다. 무보고/분모 0/비교 불가를 정상 0으로 바꾸지 않는다.

## 출력 계약

계산 코어의 `ProjectReport`가 UI 표/KPI와 두 출력기의 공통 입력이다. 주 화면의 계산 캐시를 재사용하지 않으며 문서 ID/revision/저장 상태와 대화상자 세대를 검사한다. 평준화 대안 보고가 아닌 원본 입력의 계획/잔여 예측이다. 날짜는 시간대 없는 civil date/time, 생성 시각은 UTC다.

XLSX는 공개 OOXML 형식의 ZIP32 파일이다. 사용자 문자열은 inline text로 기록하므로 `=HYPERLINK(...)` 같은 작업명도 실행 수식으로 바꾸지 않는다. 금액·공수·배정률은 서식 있는 숫자 셀, 미정은 별도 텍스트/배경이다. 음수·확인된 0이 보이며 상단 6행 고정, 자동필터, 열 너비·줄바꿈·행 높이, 인쇄 머리글을 제공한다. 날짜/ID는 ISO/문자열을 보존한다. 스냅샷 값이며 엑셀에서 JOBS 계산을 재실행하는 수식 모델은 아니다.

PDF는 Qt Gui의 `QPdfWriter`로 생성한다. 반복 페이지 머리글·출처/페이지 번호·표 머리글, 줄바꿈, 일반 행의 페이지 이동, 긴 행의 여러 페이지 이어짐을 제공한다. 긴 프로젝트명은 반복 머리글에서 말줄임하고 전체 이름은 출처 표에 보존한다. 표 전체를 작은 글자로 축소하지 않는다. 인쇄는 생성한 PDF를 OS 뷰어에서 수행한다.

앱은 Excel·Office·Python·Node·서버 설치 없이 두 형식을 생성한다. Qt 공개 API와 표준 C++만 사용하며 Office 라이브러리나 Qt private ZIP API에 의존하지 않는다. `QSaveFile` 임시 작성/원자적 commit과 협조적 `QLockFile`을 사용한다. 확장자·기존 파일·쓰기 실패는 완료 처리하지 않는다. 비협조 프로세스의 검사 직후 교체 경쟁과 동기화 폴더의 원자성은 보장 범위 밖이다.

한 보고서는 100만 셀, 출력 64 MiB, PDF 10,000페이지 한도다. 엑셀 셀 32,767자/행 표시 높이 409pt 한도를 넘으면 조용히 자르지 않고 오류를 표시한다. WBS/일별 기간을 좁히거나 PDF를 사용한다. 내보내기 중에는 해당 대화상자의 닫기/재계산을 막아 출력이 끝나도록 한다.

## 검증과 후속 범위

`reports_export`는 WBS/빈 범위·공유 과부하·기간 경계·불완전 일정·미정 가용량·F10/EAC·기준선 없는 실제·숫자/수식 텍스트·XML·기존 파일 보존·실패 원자성·긴 행/용지를 검사한다. `reports_ui`는 화면/명세 값, 필터/EAC, 파일 선택/취소, 계산 중/파일 선택 중 변경, 읽기 전용 출력을 검사한다. 기존 12개를 포함해 CTest 14개다.

`scripts/verify-report-fixtures.py build`는 생성물을 수정하지 않고 openpyxl/pypdf로 읽는다. ZIP CRC/구조, 숫자 타입·0/미정·수식 방지·출처, PDF 본문·용지 크기, 여러 페이지의 700개 구간/마지막 표식을 독립 검증한다. Python 패키지는 개발/CI 전용이다.

```sh
python -m pip install openpyxl==3.1.5 pypdf==6.10.0
python scripts/verify-report-fixtures.py build
```

Windows/macOS 출력 계약 시험은 창을 띄우지 않고 네이티브 Qt 플랫폼의 폰트를 사용한다. Windows offscreen 플러그인은 PDF 문자 폰트 엔진을 제공하지 않으므로 UI 동작 시험에만 사용한다. 실제 Windows 창과 PDF 페이지/엑셀 시트 렌더링으로 한글·정렬·줄바꿈도 별도 확인한다.

보고서 템플릿 저장/배포, 평준화 대안 보고, 간트 인쇄, 사용자 필드/피벗/엑셀 차트·양방향 재수입, PDF/A/서명, 회계·환율 연계와 대규모 성능/접근성 완전 검증은 후속 후보로 유지한다. MS Project/Primavera 파일 교환·재계산 호환성이나 제품 동등성의 완료 선언은 아니다.
