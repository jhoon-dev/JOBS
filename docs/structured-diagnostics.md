# 오류·진단 데이터와 표시

2026-10-28 사용자 승인. DIAG-01~04를 구현 전에 확정한다.

예상 가능한 도메인/계산 입력 오류는 stable code와 매개값/관련 ID를 전달한다. `what()`은 표시 언어 계약으로 사용하지 않는다. 계산 진단도 문구 대신 데이터로 구성하며, 원인을 감싼 경우 원래 코드·매개값·대상을 함께 보존한다. 계산 취소는 기존 별도 경로를 유지한다. 파일/편집 경계도 같은 진단을 표시하며 알 수 없는 표준 예외는 내부 오류로 식별하고 원래 내용을 보존한다.

Qt 없는 공통 표시 계층에서 한국어/영문 메시지와 수정 안내를 생성한다. UI와 보고서가 이 표시를 공유하며 기존 한국어 동작을 유지한다. 영문은 진단용 기반이며 전체 앱 메뉴/도움말 번역을 의미하지 않는다. 미등록 코드는 코드와 매개값을 보여 주고 잘못된 형식 문자열이나 HTML로 실행하지 않는다.

관련 작업 선택은 현재 documentId/작업 ID를 확인하고 검색/필터를 해제해 원본 작업을 선택한다. 자원/달력 오류는 관련 ID를 표시하고 가능하면 사용하는 작업과 연결한다. 문서가 닫히거나 변경된 통합 결과의 탐색은 재계산/다시 열기를 안내한다. 거부 테스트는 코드와 대상·불변 상태를 확인하며 표시 문구는 표시 계층 테스트로 분리한다.

`.jobs`와 과거 기준선/실적/시나리오 payload, 계산 정책은 변경하지 않는다. 실제 구현·코드 목록·검증 결과는 후속 절에 기록한다.

## 구현 계약

`domain/Diagnostics.h`의 `AppError`는 `ErrorCode`와 `Diagnostic`을 보존한다. `domain/ErrorCodes.h`의 명시된 토큰은 언어와 무관하다. 계산의 기존 `CONSTRAINT_CONFLICT`, `DEPENDENCY_CYCLE` 등 코드는 유지한다. `diagnosticFromException`은 원인 트리와 관련 대상 ID를 보존하며, 알 수 없는 표준 예외만 `INTERNAL_ERROR`로 감싼다. `CalculationCancelled`는 이 경로와 독립이다.

`formatting/DiagnosticCatalog.h`와 `DiagnosticText`가 한국어 문구·영문 진단 기반과 수정 안내를 담당한다. 매개값은 치환 후 다시 해석하지 않으며 UI 경고는 plain text로 표시한다. 주요 입력·파일·작업공간 오류에는 영문 설명을 제공하고, 아직 개별 번역이 없는 코드는 영문 공통 안내와 코드·매개값·관련 대상을 표시한다. 정책 설명에는 오류 수정 안내를 붙이지 않는다. 전체 메뉴·보고서 언어 선택은 이번 범위 밖이다.

문서 편집 가드, 비동기 편집 실패, 기준선 준비, 파일 파서와 원가 세부 이슈도 구조화한다. 관련 작업을 선택하면 현재 문서에 존재하는 ID인지 확인한다. 자원/달력 오류는 배정과 달력을 사용하는 작업을 찾아 선택할 수 있다. 작업공간의 다른 프로젝트 대상은 프로젝트 ID까지 확인한다.

## 검증과 재현

`structured_diagnostics`는 안정 코드·언어 렌더링·대상 ID·원인 트리·파서·worker 실패와 정책/취소 안내를 검사한다. `document_edit_guards`는 기존 거부 우선순위를 문구 대신 코드로 확인한다. `constraint_contract`는 충돌 날짜 매개값과 원인 작업 ID를 확인한다. 공유 자원 과부하 코드가 일반 공수 오류로 잘못 분류되지 않는 표시 회귀도 포함한다.

전체 실행은 `ctest --test-dir build --output-on-failure`, 네이티브 작업공간 검증은 `python scripts/check-workspace-native.py build`다. [소스 버전별 검증 기록](validation/workspace-2026-10-28/README.md)에 전체 결과와 범위를 기록한다.
